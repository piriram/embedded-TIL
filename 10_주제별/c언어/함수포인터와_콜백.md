# 함수 포인터와 콜백

**원본 강의:** [Function pointers and callbacks (YouTube)](https://www.youtube.com/watch?v=sxTFSDAZM8s)

함수 포인터는 **함수의 주소를 저장하는 포인터**이고, callback은 그 주소를 다른 함수에 전달해 필요할 때 간접 호출하게 만드는 설계다. 알고리즘의 공통 흐름은 하나로 유지하면서 비교·판단·처리 규칙만 교체할 수 있으므로, 정렬·event handling·driver abstraction에서 널리 쓰인다.

---

## 1. 함수의 주소와 함수 포인터 선언

함수 이름 뒤에 호출 연산자 `()`를 붙이면 함수를 실행한다. 반대로 함수 이름만 쓰거나 `&`를 붙이면 대부분의 식 문맥에서 그 함수의 주소를 얻을 수 있다.

```c
void greet(void)
{
    puts("hello");
}

void (*action)(void) = &greet;

action();       /* greet()를 간접 호출 */
(*action)();    /* 같은 의미. 역참조가 더 명시적 */
```

`void (*action)(void)`은 “인자가 없고 `void`를 반환하는 함수를 가리키는 포인터”다. 괄호가 없으면 완전히 다른 선언이 된다.

```c
int (*fn)(int, int);  /* int 두 개를 받아 int를 반환하는 함수 포인터 */
int *fn(int, int);    /* int*를 반환하는 함수 — 함수 포인터가 아님 */
```

함수 포인터가 받을 인자 타입과 반환 타입은 대상 함수의 signature와 맞아야 한다. 맞지 않는 함수 포인터로 호출하면 undefined behavior가 될 수 있으므로, 억지 cast로 compiler warning을 없애면 안 된다.

## 2. callback의 가장 작은 구조

callback은 호출할 함수를 caller가 직접 고정하지 않고, 호출자에게서 함수 주소를 받아 나중에 실행하는 구조다.

```c
typedef void (*Callback)(void);

void run_when_ready(Callback callback)
{
    /* 준비 작업 */
    callback();
}

void on_ready(void)
{
    puts("ready");
}

int main(void)
{
    run_when_ready(on_ready);
}
```

흐름은 다음과 같다.

```text
main ──on_ready의 주소──> run_when_ready
                                  │
                            callback()로 간접 호출
                                  ↓
                              on_ready 실행
```

`typedef`를 쓰면 복잡한 declarator를 API의 의미 있는 이름으로 바꿀 수 있다. callback을 받는 함수는 “무엇을 할지”가 아니라 “언제 호출할지”에 집중하고, 동작은 caller가 주입한다.

## 3. 중복 없이 정렬 기준 바꾸기

버블 정렬의 swap·반복 로직은 같지만, 오름차순·내림차순·절댓값순은 비교 규칙만 다르다. 이 규칙을 함수 포인터로 분리하면 알고리즘을 복제하지 않아도 된다.

```c
typedef int (*CompareInt)(int left, int right);

void bubble_sort(int values[], size_t count, CompareInt compare)
{
    for (size_t i = 0; i < count; ++i) {
        for (size_t j = 0; j + 1U < count - i; ++j) {
            if (compare(values[j], values[j + 1U]) > 0) {
                int temp = values[j];
                values[j] = values[j + 1U];
                values[j + 1U] = temp;
            }
        }
    }
}

int ascending(int left, int right)
{
    return (left > right) - (left < right);
}

int descending(int left, int right)
{
    return ascending(right, left);
}
```

`ascending`과 `descending`은 양수·0·음수라는 contract를 지킨다. 단순히 `left - right`를 반환하는 방식은 큰 정수에서 overflow할 수 있으므로, 비교만 필요하다면 위처럼 관계식을 반환하는 편이 안전하다.

## 4. 표준 라이브러리 `qsort()`의 일반화

`qsort()`는 어떤 타입의 배열도 정렬할 수 있도록 비교 callback을 `const void *` 두 개로 받는다.

```c
#include <stdlib.h>

static int compare_int_ascending(const void *left, const void *right)
{
    const int a = *(const int *)left;
    const int b = *(const int *)right;

    return (a > b) - (a < b);
}

int values[] = { 3, -1, 8, 2 };
qsort(values, 4U, sizeof values[0], compare_int_ascending);
```

`qsort()`은 배열 원소의 주소를 callback에 전달하고, callback은 실제 타입으로 cast한 뒤 값을 읽는다. `const void *`는 “임의 타입 객체를 읽을 수 있는 generic pointer”라는 뜻이며, 비교 함수가 원소를 바꾸지 않겠다는 약속도 표현한다.

> **주의**
> callback에 `NULL`이 올 수 있는 API라면 호출 전에 검사해야 한다. callback 안에서 오래 걸리는 작업·blocking·재진입 위험이 있는 일을 하면 API의 timing과 state를 복잡하게 만들 수 있다.

## 5. 임베디드에서의 callback과 ISR의 관계

driver가 event가 발생했을 때 application handler를 부르는 구조는 callback의 대표 사례다.

```c
typedef void (*ButtonCallback)(void *context);

struct Button {
    ButtonCallback on_pressed;
    void *context;
};
```

`context` pointer를 함께 전달하면 전역 변수 하나에 의존하지 않고 여러 instance를 구별할 수 있다. 다만 lifetime을 보장해야 한다. 등록한 callback이나 context가 사라진 뒤 ISR·driver가 호출하면 dangling pointer 문제가 생긴다.

ISR도 “저장된 함수 주소로 분기한다”는 점에서는 callback과 닮았지만, 일반 callback과 동일하지는 않다.

- 일반 callback은 software가 정한 시점에 보통 현재 호출 stack 안에서 실행한다.
- ISR은 hardware exception이 CPU 실행을 선점하며, vector table의 정해진 slot에서 handler 주소를 얻는다.
- ISR은 interrupt context와 제약된 timing에서 실행되므로 짧게 끝내고, 긴 일은 flag·queue·task로 넘긴다.

이 연결은 [벡터 테이블·예외·인터럽트 핸들러](../cs/임베디드수업/15_스타트업코드_벡터테이블_예외_ISR.md)에서 이어서 다룬다.

- **왜 필요:** 공통 알고리즘은 유지하면서 비교·event 처리처럼 바뀌는 동작만 교체해 중복 code와 조건문 분기를 줄일 수 있다.

- **비교:** 일반 callback은 software가 호출 시점을 정하지만, ISR은 hardware가 vector table의 handler 주소를 읽어 실행한다. 둘 다 함수 주소를 쓰지만 실행 context와 timing 제약이 다르다.
- **30초 통합 답변:**
  > 함수 포인터는 함수의 주소를 저장하는 포인터이고, callback은 그 주소를 다른 함수에 전달해 필요할 때 간접 호출하는 방식입니다. 예를 들어 정렬의 반복과 swap은 하나로 두고 비교 함수만 callback으로 받으면 오름차순·내림차순을 중복 없이 바꿀 수 있습니다. 선언은 `int (*compare)(int, int)`처럼 괄호가 중요하며, 대상 함수의 signature가 반드시 맞아야 합니다. 임베디드에서는 driver callback과 ISR dispatch가 함수 주소를 사용한다는 점은 비슷하지만, ISR은 hardware가 선점해 실행하므로 더 짧고 예측 가능하게 설계해야 합니다.

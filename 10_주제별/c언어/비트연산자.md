# 비트 연산자 (Bitwise Operators)

**원본 강의:** [Bitwise Operators and WHY we use them (YouTube)](https://www.youtube.com/watch?v=igIjGxF2J-w)

---

## 1. 비트 연산자를 왜 알아야 하나

비트 연산자는 변수의 개별 비트(bit)에 직접 작용하는 연산자다. 요즘은 메모리가 넉넉해서 안 써도 그럭저럭 살 수 있지만, 다음 영역에서는 여전히 필수다.

- **암호화·영상 압축 알고리즘**: 비트 단위 변환이 핵심.
- **임베디드 장치**: 메모리·연산 자원이 제한적이라 비트로 짜내야 한다.

핵심은 **공간 절약**이다. CPU가 참조할 수 있는 최소 단위는 1 byte이기 때문에, `bool` 변수는 사실 0/1 두 값만 쓰면서도 1 byte(8 bit)를 통째로 차지한다. 나머지 7 bit는 그냥 패딩이다. 작은 디바이스에서 플래그 수십 개를 다루면 이게 큰 낭비가 된다.

그래서 프로그래머는 **여러 boolean flag를 한 byte에 몰아넣는다.** 1 byte = 8 bit이므로, 한 변수에 최대 8개의 독립 플래그를 저장할 수 있다. 이 트릭이 실전에서 가장 잘 보이는 곳이 다음 절의 Unix 파일 권한이다.

> **주의**
> bool 하나가 1 byte를 먹는다는 사실은 일반 데스크톱 코드에서는 무시해도 되지만, MCU 펌웨어처럼 RAM이 수 KB뿐인 환경에서는 의사결정에 영향을 준다.

---

## 2. 실전 예제 — Unix 파일 권한

`644`, `777` 같은 파일 권한 숫자는 3개의 그룹으로 구성된다.

- 첫째 숫자: **owner**의 권한
- 둘째 숫자: **group**의 권한
- 셋째 숫자: **everyone else(others)**의 권한

각 숫자는 8진수 한 자리이고, 이걸 **3 bit 이진수**로 풀면 `read / write / execute` 세 개의 비트 플래그가 된다.

| 10진 | 2진 | 의미 |
|------|-----|------|
| 7 | `111` | read + write + execute |
| 6 | `110` | read + write |
| 4 | `100` | read only |

이 예시를 머릿속에 두고 6개의 비트 연산자를 하나씩 본다. 즉 "비트 연산자 = 권한을 검사·결합·제거하는 도구"라는 시각으로 읽으면 직관이 빨리 생긴다.

---

## 3. AND (`&`) — 권한이 있는지 검사

두 비트가 **둘 다 1**일 때만 결과가 1. 한쪽이라도 0이면 결과는 0.

```
  7 = 111
  6 = 110
-------- AND
  6 = 110
```

행별로 보면 위 두 행은 `1 & 1 = 1`, 마지막 행은 `1 & 0 = 0` → 결과 `110` = 6.

**용도: 권한 보유 여부 테스트.** 사용자의 권한과 "요구되는 권한"을 AND 하면, 일치하는 비트만 남는다.

- 요구 권한과 결과가 같으면 → 권한 있음
- 결과가 0이면 → 권한 없음

> 강사: "AND는 매칭되는 비트만 돌려주기 때문에, 그 자체로 권한 체크 테스트가 된다."

---

## 4. OR (`|`) — 권한을 결합/추가

두 비트 중 **하나라도 1**이면 결과가 1.

```
  5 = 101
  6 = 110
-------- OR
  7 = 111
```

**용도 1: 권한 결합.** read + write를 한 번에 부여하고 싶을 때.

```c
int read  = 0b100;   // 4
int write = 0b010;   // 2
int perm  = read | write;   // 0b110 = 6
```

**용도 2: 기존 값에 권한 추가.** OR 대입 연산자 `|=`를 쓴다.

```c
int perm = 6;        // 현재 read + write
perm |= 0b001;       // execute 추가
// perm == 7 (read + write + execute)
```

`|=`는 **기존 비트를 보존하면서 특정 비트만 켜는 표준 관용구**다. MCU 레지스터 설정에서 거의 항상 이 패턴이 나온다.

---

## 5. XOR (`^`) — 다를 때만 1, 권한 제거/토글

두 비트가 **서로 다를 때**만 결과가 1. 같으면 0.

```
  5 = 101
  6 = 110
-------- XOR
  3 = 011
```

첫 행 `1 ^ 1 = 0`, 둘째·셋째는 `0/1` 또는 `1/0` 조합 → 결과 `011` = 3.

**용도: 특정 권한 제거(혹은 토글).** read+write 상태에서 write만 꺼버리고 싶다면:

```c
int perm = 0b110;        // read + write
perm ^= 0b010;           // write 비트 토글 → 끔
// perm == 0b100 (read only)
```

XOR은 "켜져 있던 비트는 끄고, 꺼져 있던 비트는 켠다" → 다시 같은 값으로 XOR 하면 원상복귀. 그래서 **토글 동작**이나 **간단한 반전 암호**에 활용된다.

> **주의**
> XOR로 비트를 "끄려면" 끄려는 비트가 **현재 1이라는 사실을 알고 있어야** 한다. 모르면 오히려 켜진다. 안전하게 끄려면 `perm &= ~mask`(AND + NOT 조합)을 쓰는 게 일반적이다.

---

## 6. NOT (`~`) — 모든 비트 반전

지금까지의 연산자는 모두 두 값을 입력받았지만, NOT은 **단항 연산자**다. 값 하나의 모든 비트를 뒤집는다.

```
   5 = 00000101
  ~5 = 11111010
```

Python 등에서 `~5`를 출력하면 `-6` 같은 음수가 나오는데, 이건 **2의 보수(two's complement) 표현** 때문이다.

- 부호 있는 byte의 **최상위 비트**가 부호 비트.
- 그 비트가 1이면 음수.
- 8-bit 2의 보수에서 `11111010`의 값은 `-128 + 64 + 32 + 16 + 8 + 2 = -6`.

즉 NOT은 **순수한 비트 반전 자체**일 뿐이고, 결과가 음수처럼 보이는 건 정수형이 부호 있는 2의 보수 표현이기 때문이다. unsigned로 캐스팅하면 큰 양수가 된다.

**실전 용도:** 마스크 만들기. 특정 비트만 끄고 싶을 때 `perm &= ~mask` 패턴.

> **예외**
> 언어와 정수 크기에 따라 `~5`의 결과 표시가 달라진다. C에서 `unsigned char`라면 `250`, Python의 임의정밀도 정수에서는 `-6`. 비트 패턴 자체는 같지만 해석이 다르다는 점을 항상 의식해야 한다.

---

## 7. Shift — `<<` (left) / `>>` (right)

비트 전체를 왼쪽 또는 오른쪽으로 N칸 밀어준다. NOT처럼 단항이지만, 두 번째 피연산자는 "몇 칸 이동할지"를 의미한다.

### 7-1. Left shift `<<`

```
  5 = 00000101
5 << 2 = 00010100   (= 20)
```

왼쪽 끝으로 밀려난 비트는 **버려진다**. 위 예시에선 0이라 영향이 없지만, 상위 비트에 1이 있었다면 값이 잘려나간다.

수학적으로 `x << n`은 `x * 2^n`. 위 예시는 5 × 4 = 20.

### 7-2. Right shift `>>`

```
 20 = 00010100
20 >> 2 = 00000101   (= 5)
```

`x >> n`은 `x / 2^n` (소수점 버림). 곱셈·나눗셈보다 비트 시프트가 빠른 환경(예전 CPU, MCU)에서 자주 쓰였다.

### 7-3. 비트 위치 만들기

shift는 **"N번 비트 자리만 1인 마스크"**를 만드는 표준 방법이기도 하다.

```c
#define LED_PIN  (1U << 5)   // 0b00100000, 즉 비트 5만 1
GPIOA->BSRR = LED_PIN;       // 비트 5에 해당하는 GPIO 핀 set
```

이 패턴은 임베디드 레지스터 조작 코드 전반에서 압도적으로 자주 나온다.

---

## 8. 비트 마스크 — 원하는 자리만 골라 보존·변경하기

**비트 마스크(bit mask)** 는 관심 있는 비트에만 `1`을 둔 값이다. 레지스터 전체를 덮어쓰지 않고 필요한 비트만 검사하거나 바꾸려면, 먼저 마스크를 만든 뒤 AND/OR/NOT과 조합한다. `1U << N`은 N번 비트에만 1이 있는 마스크를 읽기 좋게 만드는 표준 표기다.

```c
#define BIT(n)  (1U << (n))

if ((reg & BIT(7)) != 0U) {  // bit 7이 1인지 검사
    // ...
}

reg |= BIT(7);               // bit 7 set, 나머지는 보존
reg &= ~BIT(7);              // bit 7 clear, 나머지는 보존
reg ^= BIT(7);               // bit 7 toggle, 나머지는 보존
```

`&`의 마스크 비트가 `1`이면 원래 값을 통과시키고 `0`이면 결과를 0으로 만든다. 반대로 `|`의 마스크 비트가 `1`이면 결과를 강제로 1로 만든다. 그래서 clear에는 `& ~mask`, set에는 `| mask`가 쓰인다.

### 여러 비트로 된 필드 설정

레지스터에는 한 비트짜리 enable뿐 아니라, STM32 `MODER`처럼 **핀 하나에 2비트**를 쓰는 필드도 있다. 예를 들어 PA9와 PA10의 mode 필드(비트 18~21)를 모두 지운 뒤, 두 핀을 `01`(general-purpose output)로 만들려면 다음 순서가 필요하다.

```c
#define PA9_PA10_MODE_Msk  (0xFU << 18U)  // bits 18~21 모두 선택
#define PA9_PA10_OUT_Msk   (0x5U << 18U)  // 01 at [19:18], 01 at [21:20]

GPIOA->MODER &= ~PA9_PA10_MODE_Msk;       // 해당 4비트만 00으로 clear
GPIOA->MODER |=  PA9_PA10_OUT_Msk;        // bit 18, 20만 set
```

한 식으로도 쓸 수 있다.

```c
GPIOA->MODER = (GPIOA->MODER & ~PA9_PA10_MODE_Msk)
             |  PA9_PA10_OUT_Msk;
```

이것은 **다른 field를 보존하면서 목표 field를 원하는 값으로 교체**하는 일반식이다. `0xF`는 폭 4비트의 모든 자리를 고르는 mask이고, 실제 쓸 값 `0x5`는 해당 field 폭 안에 들어가야 한다.

> **주의**
> 위 field 설정은 `GPIOA->MODER`를 읽고 수정해 다시 쓰는 RMW(read-modify-write)다. 초기화처럼 한 실행 흐름만 해당 설정 레지스터를 만지는 상황에는 보통 적절하지만, ISR·다른 태스크·하드웨어가 같은 레지스터를 동시에 갱신할 수 있다면 보호 방법 또는 주변장치가 제공하는 atomic set/reset 레지스터를 확인해야 한다. GPIO 출력 latch의 경우 STM32 `BSRR`가 그 해법이다.

## 9. `1U << n`과 shift를 안전하게 읽는 법

`1U`의 `U`는 `unsigned int` 리터럴이라는 뜻이다. 레지스터 mask를 만들 때 `1 << n` 대신 `1U << n`을 쓰면, 부호 비트와 signed left shift 문제를 피하고 "이 값은 비트 패턴"이라는 의도도 드러난다.

```c
#define BIT(n)  (1U << (n))
```

- `n`은 반드시 피연산자 비트 폭보다 작아야 한다. 보통 32-bit `unsigned int`에서 `1U << 32`는 유효한 bit 32를 만드는 식이 아니라 **정의되지 않은 동작**이다.
- `1U << n`은 `n`번 비트 하나만 세우는 데 적합하다. 32-bit 레지스터에는 `uint32_t`/`UINT32_C(1)`처럼 레지스터 폭을 명시한 타입을 쓰면 더 분명할 수 있다.
- unsigned 값의 left shift는 버려지는 상위 비트가 있을 수 있으므로, "항상 `2^n`을 곱한다"가 아니라 **표현 가능한 범위 안에서** 그 관계가 성립한다고 이해한다.
- 양수의 right shift는 0을 채우는 logical shift처럼 보이지만, **음수 signed 값의 right shift 결과는 C 언어에서 implementation-defined**다. 1번 강의의 ARM 예제에서는 arithmetic shift로 부호 비트를 채워 `-값 / 2^n`에 가까운 결과가 나왔지만, 이 동작을 이식 가능한 코드의 전제로 두지 않는다. 비트 필드 처리에는 unsigned 타입을 우선 사용한다.

## 10. 한눈에 정리

| 연산자 | 기호 | 입력 수 | 핵심 규칙 | 대표 용도 |
|--------|------|---------|----------|----------|
| AND | `&` | 2 | 둘 다 1이면 1 | 특정 비트가 켜져 있는지 검사, 비트 마스킹 |
| OR  | `|` | 2 | 하나라도 1이면 1 | 특정 비트 켜기 (`|=`) |
| XOR | `^` | 2 | 다를 때만 1 | 비트 토글, 값 비교, 간이 암호 |
| NOT | `~` | 1 | 모든 비트 반전 | 마스크 반전 (`&= ~mask`로 비트 끄기) |
| Left shift | `<<` | 1 (+ shift 수) | 왼쪽으로 N칸 이동 = `× 2^N` | 비트 위치 마스크 생성 |
| Right shift | `>>` | 1 (+ shift 수) | 오른쪽으로 N칸 이동 = `÷ 2^N` | 필드 추출, 나눗셈 최적화 |

표준 관용구 세 가지만 외우면 80%는 끝난다.

```c
reg |=  (1U << N);      // 비트 N 켜기
reg &= ~(1U << N);      // 비트 N 끄기
reg ^=  (1U << N);      // 비트 N 토글
if (reg & (1U << N)) {  // 비트 N 켜져 있는지 검사
    ...
}
```

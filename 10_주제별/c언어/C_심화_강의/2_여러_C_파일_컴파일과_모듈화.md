# 여러 C 파일 컴파일과 모듈화

**원본 강의:** [Compiling C programs with Multiple Files — Jacob Sorber (YouTube)](https://www.youtube.com/watch?v=2YfM-HxQd_8)

## 1. 번역 단위와 linker

각 `.c` 파일과 그 `#include` 결과는 하나의 **translation unit**이다. compiler는 각각을 `.o`로 만들고, linker가 참조와 정의를 연결한다.

```text
main.c -> main.o ┐
uart.c -> uart.o ├-> link -> executable / firmware
startup.c -> startup.o ┘
```

그래서 선언이 맞아 컴파일되더라도 구현 object가 빠지면 `undefined reference`가 link 단계에서 난다.

## 2. 헤더는 계약, `.c`는 구현

```c
// uart.h
#ifndef UART_H
#define UART_H
#include <stddef.h>
void uart_init(unsigned long baud);
void uart_send(const unsigned char *data, size_t len);
#endif

// uart.c
#include "uart.h"
static unsigned long current_baud;
void uart_init(unsigned long baud) { current_baud = baud; }
```

`.h`에는 공개 선언·타입·매크로를, `.c`에는 함수와 전역 객체의 실제 정의를 둔다. 헤더의 include guard는 간접 중복 포함을 막고, 헤더는 쓰는 타입의 표준 헤더를 스스로 포함해야 한다.

> **주의**
> `#include`는 텍스트 삽입일 뿐 구현을 합치는 명령이 아니다. 결합은 linker가 한다.

## 면접 답변 (30초 분량)

- **한 줄 정의:** C 모듈화는 헤더의 공개 계약과 `.c`의 단일 구현 정의를 linker가 결합하는 방식이다.
- **왜 필요:** 구현을 감추면서 여러 파일이 일관된 API와 타입을 공유한다.
- **동작:** 각 `.c`는 독립 컴파일되고, linker가 선언된 참조를 실제 정의와 연결한다.
- **비교:** `#include`는 전처리, link는 object file 결합이다.
- **30초 통합 답변:**
  > C에서는 각 `.c`를 독립 번역 단위로 컴파일한 뒤 linker가 object file의 심볼을 연결합니다. 따라서 헤더에는 함수 선언, 타입, 매크로를 두고 실제 함수와 전역 변수 정의는 하나의 `.c`에만 둡니다. include guard와 self-contained header를 지키고, undefined reference가 나면 구현 object나 library가 link에서 빠졌는지 확인합니다.

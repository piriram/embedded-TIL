## 1. ADC가 필요한 이유

전압·전류·온도 같은 물리량은 **연속 신호(아날로그)** 다. 이를 디지털 세상에서 쓰려면 **디지털로 변환**해야 하고, 그 변환기가 **ADC(Analog-Digital Converter)** 다.

- 대부분의 센서(90% 이상)는 물리량을 **전압으로 변환**해 측정한다. 전압·전류·온도·빛·토크 등을 전압으로 바꿔 ADC에 넣고, 디지털 값에서 역산해 물리량을 복원한다.

> **주의 — 입력 전압은 기준 전압(3.3V) 이내.**
> F767의 ADC 전원은 **3.3V**다. 입력 전압도 **3.3V 이내**여야 한다. 예: 전기차의 800V를 측정하려면 그대로 넣으면 MCU가 터진다. **저항 분압**으로 3.3V 이내로 낮춰서 넣는다.

---

## 2. 변환 3단계 — 샘플링 · 양자화 · 부호화

아날로그(연속) → 디지털(이산) 변환은 세 단계를 거친다. MCU 내부 ADC가 알아서 처리하지만 원리는 알아두자.

1. **샘플링(Sampling)** — 일정한 주기로 신호를 채취. **가로축(시간) 분할.** ADC 샘플링은 **클럭에 동기화**되므로 **MCU 클럭이 빠를수록 샘플링도 빠르다.**
2. **양자화(Quantization)** — 샘플 값을 **세로축 기준(분해능)** 으로 나눔. 예: 4비트면 2⁴=16단계(0~15).
3. **부호화(Encoding)** — 나눈 세로축 단계에 코드(비트값)를 부여.

> **나이퀴스트(Nyquist) 이론:** 샘플링 주파수는 원 신호 주파수의 **2배 이상**이어야 한다. 실제로는 훨씬 빠르게 샘플링해서 보통 문제없다.

> **이미지 필요**
> 샘플링·양자화·부호화 3단계 그림 — 연속 신호를 시간축으로 샘플 → 세로축 분할 → 코드 부여
> - 출처: 강의 슬라이드 2:01~2:03
> - 대체안: ADC 변환 개념도

## 3. 분해능(Resolution) — 비트 수가 정밀도

ADC 비트가 높을수록 분해능이 높아 **정밀한 데이터**를 얻는다. F767은 ADC를 **12~6비트**로 설정 가능하고, 이 강의는 **항상 12비트**를 쓴다.

기준 전압 3.3V를 비트 수만큼 나눈다.

| 비트 | 단계 수 | 1스텝 크기(3.3V 기준) |
| --- | --- | --- |
| 8비트 | 256 (0~255) | 약 **12.89 mV** |
| 12비트 | 4096 (0~4095) | 약 0.8 mV |
| 16비트 | 65536 | 약 **0.05 mV** |

비트가 높을수록 스텝이 촘촘해진다. 8비트와 16비트는 엄청난 차이가 난다.

---

## 4. ADC 오차 3종

1. **양자화 오차(Quantization Error)** — 연속 신호를 이산값으로 근사할 때 **필연적으로** 생긴다. 실제 값이 단계 사이에 있으면 가까운 코드로 뭉뚱그려진다. **비트가 높을수록(세로축 촘촘) 줄어든다.**
2. **오프셋 오차(Offset Error)** — 내부 ADC 회로나 외부 센서 회로의 불균형으로 **일정한 상수만큼** 어긋남. 상수라서 **소프트웨어로 보정 쉬움**(빼거나 더함). 삼상 인버터 전류 센서에서 오프셋 보상 코드를 작성할 예정.
3. **이득 오차(Gain Error)** — **일정한 값을 곱한 것 같은 기울기 오차**. 특정 값을 곱해 소프트웨어로 보정.

---

## 5. 출력 계산 공식

분해능 n비트 ADC의 출력:

```
ADC_OUT = (2^n - 1) × (V_in / V_ref)
```

예: 12비트, V_in=1V, V_ref=3.3V →
`ADC_OUT = 4095 × (1 / 3.3) ≈ 1240`

이 디지털 값을 역산하면 물리량(전압)으로 환산할 수 있다.

```c
voltage = (adc_raw * V_REF) / 4095.0;
```

> **주의:** 입력 전압은 항상 V_ref(3.3V) **이하**. 넘으면 ADC가 고장 난다.

## 6. SAR ADC 구조

F767은 **SAR(Successive Approximation Register) ADC**를 쓴다. (시그마-델타 등 다른 종류도 있음.) 두 단계로 구성된다.

1. **Sample & Hold (S/H)** — 클럭에 동기화된 스위치가 ON되면 입력 전압이 **캐퍼시터에 충전**된다.
2. **변환(Conversion)** — 스위치 OFF 후, 충전된 전압과 내부 **DAC**를 **비교기**로 비교해 내부 로직으로 디지털 출력을 만든다.

### 6.1 샘플링 타임과 변환 타임

- **Total Conversion Time = Sampling Time + 12 cycle**. (12 사이클은 변환에 무조건 필요한 고정 시간, 클럭 기준.)
- 예: ADC 클럭 30MHz, 샘플링 3사이클 → 총 15사이클.
- 샘플링 타임은 **`ADC_SMPR`** 레지스터로 설정.

> **주의 — 샘플링 타임의 트레이드오프.**
> 샘플링 타임이 **짧으면 빠르지만**, 캐퍼시터 충전 시간이 부족해 **데이터가 부정확**할 수 있다. 실험적으로 정하는 경우가 많다 — 최소(3사이클)로 시작해 부정확하면 조금씩 늘려 정밀도를 높인다. **속도 vs 정밀도** 트레이드오프.

---

## 7. 레귤러 / 인젝티드 그룹

F767 ADC는 16채널을 두 그룹으로 임의 분할해 쓸 수 있다.

- **Regular 그룹** — 일반 채널. 데이터는 **`ADC_DR`** 에 저장.
- **Injected 그룹** — 최대 4채널, 각각 데이터 레지스터(**`ADC_JDR`**) 보유. **우선순위가 더 높다.**

> **우선순위:** Regular 시퀀스 동작 중 Injected 트리거가 오면 **Regular를 중단하고 Injected 먼저** 처리 후 Regular 재개. 반대로 Injected 동작 중엔 Regular 트리거가 와도 Injected를 다 끝내고 Regular를 한다.

> Injected의 JOFR 레지스터에 오프셋을 미리 넣어두면 변환 결과에서 빼서 저장하므로 JDR이 음수가 될 수 있다(SET 비트로 부호 확인). 이 강의 실습/인버터는 **Regular 채널만** 사용.

데이터 정렬은 좌측/우측 정렬(Left/Right Alignment) 선택 가능. 외부 16채널 외에 **내부 입력 채널 3개**가 있어 배터리 전압·1.21V 측정 등에 쓰는데, 내부 채널은 샘플링 시간을 10µs 이상 크게 잡으라고 데이터시트가 권장하며 정밀도가 그리 높지 않다.

---

## 8. 변환 모드

- **Single Conversion** — 트리거(스타트 신호)마다 한 채널을 1회 변환하고 끝.
- **Continuous Conversion** — 스타트 트리거 1번이면 그 뒤로 계속 반복 변환.
- **Scan 모드** — 채널과 순서를 미리 정의해 채널 1→2→3… 순차 변환. Single이면 한 바퀴, Continuous면 끝나면 처음부터 무한 반복.

## 9. 실습 — 스로틀 신호 측정 (PA7)

스로틀이 PA7에 연결돼 있다. **Single 채널 + Single Conversion**으로 스로틀을 돌리며 전압 변화를 확인한다.

> **회로:** 스로틀은 0~5V로 동작. ADC 입력은 3.3V 이내여야 하므로 R7·R12 저항으로 **분압**해 ADC에 넣는다. C는 노이즈 방지용 바이패스 캐퍼시터.

### 설정 순서

1. **`init_MCU()`** — 클럭 초기화(클럭 편 참고).
2. **GPIOA 클럭 enable** (PA7 사용).
3. **PA7을 Analog 모드(`11`)** — `GPIOA_MODER`의 해당 2비트를 11로. ADC로 쓰려면 Analog 모드 필수.
4. **ADC 클럭 enable** — ADC1/2/3은 **APB2** 연결. `RCC_APB2ENR`로 enable.
5. **`ADC_CCR`** 의 프리스케일러 = 6분주 → APB2 54MHz ÷6 = **ADC 9MHz**.
6. **`ADC_CR2`** 의 ADON 비트=1 → ADC enable.
7. **`ADC_SMPR2`** — 채널 7 샘플링 타임 = `011`(56 사이클, 중간값).
8. **`ADC_SQR3`** — 첫 번째 시퀀스에 채널 7 설정(1회 변환).

### 변환 루프

```c
while (1) {
    ADC1->CR2 |= (1 << 30);                 // SWSTART: Regular 변환 시작
    while (!(ADC1->SR & (1 << 1)));         // EOC(End Of Conversion) 대기
    adc_raw = ADC1->DR;                     // 데이터 레지스터 읽기 (uint16)
    throttle_V = adc_raw * V_REF / 4095.0;  // 전압 환산
}
```

- `SWSTART`(CR2 30번 비트)로 소프트웨어 변환 시작.
- ADC는 변환에 시간이 걸리므로, **`ADC_SR`의 EOC 비트**가 1(변환 완료)이 될 때까지 폴링.
- 완료되면 `ADC_DR`에서 raw 값을 읽어 전압으로 환산.

> **실습 결과:** ST-Link 전원(3.3V)만 공급한 상태라 스로틀을 끝까지 당겨도 약 1.16V까지만 오른다(정상). 스로틀을 놓으면 약 0.48V. 나중에 36V 배터리를 연결하면 더 높이 올라간다.

- **왜 필요:** 전압·전류·온도 등 물리량은 연속 신호라 디지털로 처리하려면 변환이 필요하다. 입력은 반드시 기준전압 3.3V 이내여야 한다.

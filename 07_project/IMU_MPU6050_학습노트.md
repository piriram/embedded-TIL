# IMU(MPU6050) 센서 기반 통신 프로젝트

## 1. 환경 세팅 복기 (Mac & STM32CubeIDE)

### [개념 요약]
Mac 환경에서 STM32 마이크로컨트롤러를 개발하기 위해 **STM32CubeMX**(독립 실행형)와 **STM32CubeIDE**를 연동하는 워크플로우를 구축했다. 핀맵(SYS, RCC, PC13, USART1)을 먼저 구성하고 IDE로 프로젝트를 가져오는 방식을 사용했다.

### [핵심 원리/공식]

| 설정 항목 | 설정 값 / 목적 | 비고 |
| :--- | :--- | :--- |
| **SYS** | Serial Wire | ST-Link를 통한 디버깅 및 프로그래밍 용도 |
| **RCC** | High Speed Clock (HSE) | 외부 크리스탈을 사용해 더 정확한 클럭 제공 |
| **PC13** | GPIO_Output | 동작 테스트용 내장 LED 제어 |
| **USART1** | Asynchronous | UART 통신을 통한 데이터 출력 (모니터링) |

> CubeMX에서 `.ioc` 코드를 생성한 뒤, CubeIDE에서 `Import -> Existing Projects into Workspace`로 불러오는 워크플로우를 따른다.

### [구현 코드 스니펫]
```bash
# Mac 환경에서 디버깅 시 자주 발생하는 st-link-server 에러 해결을 위한 명령어 (패키지 설치 및 재실행)
$ brew install stlink
```

> **주의**
> Mac 환경에서는 USB 권한이나 프로세스 충돌로 인해 `st-link-server` 오류가 빈번하다. 오류 발생 시 백그라운드 프로세스를 확인하거나 관련 패키지를 재설치해야 할 수 있다.

## 2. 디버깅 복기 (하드웨어 결함의 소프트웨어적 증명)

### [개념 요약]
I2C 통신을 Bit-banging으로 구현하던 중, **SDA 라인이 GND로 합선(Stuck Low)**되는 하드웨어 결함을 경험했다. 이를 오실로스코프 없이 디버거와 `volatile` 키워드를 활용해 소프트웨어적으로 완벽하게 증명했다.

### [핵심 원리/공식]
- **I2C ACK (Acknowledge) 원리:** 데이터 송신 후, 정상적으로 데이터를 수신했다면 수신 측(Slave)이 SDA 라인을 강제로 Low(0)로 당겨 ACK 신호를 보낸다. (정상 ACK = 0, NACK = 1)
- **Stuck Low 검증 논리:** Slave(센서)가 연결되지 않았거나 통신에 실패했다면 NACK(1)이 읽혀야 하지만, 단선이나 합선이 발생해 무조건 0이 읽히는 현상을 디버거로 포착했다.

### [구현 코드 스니펫]
```c
// [뼈대 코드] 디버거로 관찰하기 위해 최적화를 방지하는 키워드 적용
_____ uint8_t sda_state = 0; 
uint8_t ack_status = 1; // 기본값 NACK

// I2C Write 후 ACK 체크 (Bit-banging)
// SDA 핀 상태를 읽어 ack_status에 저장하는 HAL 함수 로직 작성
ack_status = _________________________________;

if (ack_status == 0) {
    // 정상적인 ACK인지, GND 합선으로 인한 비정상 0인지 판단하는 디버깅 로직 고민하기
}
```

> **주의**
> 컴파일러 최적화로 인해 하드웨어 레지스터 값이 캐싱되면 디버거 창에서 값이 갱신되지 않는다. 핀 상태를 실시간으로 추적하려면 반드시 변수에 **`volatile`** 키워드를 선언해야 한다.

## 3. 모니터링 기법 (Live Expressions 활용)

### [개념 요약]
UART to USB 컨버터(CH340 등) 모듈이나 복잡한 터미널 프로그램 없이, STM32CubeIDE의 내장 기능인 **Live Expressions**를 이용해 센서의 Raw 데이터를 실시간으로 모니터링했다.

### [핵심 원리/공식]
- **Live Expressions 동작 원리:** ST-Link 디버거의 **SWD(Serial Wire Debug)** 인터페이스를 통해 프로그램 실행을 멈추지(Halt) 않고도 백그라운드에서 메모리 값을 주기적으로 샘플링하여 렌더링한다.

### [구현 코드 스니펫]
```c
// [뼈대 코드] 센서 데이터를 담을 전역 구조체 선언
typedef struct {
    int16_t accel_x;
    int16_t accel_y;
    int16_t accel_z;
    // ... gyro 데이터 등 ...
} MPU6050_Data_t;

// Live Expressions에 등록하여 실시간으로 확인할 전역 변수
MPU6050_Data_t sensor_data; 
```

> **주의**
> 지역 변수(Local variable)는 스택 메모리에 할당되었다 사라지므로 모니터링이 불가하다. 툴에서 값을 계속 추적하려면 **전역 변수(Global variable)**로 선언해야 한다.

### [나만의 필기 공간]
> Live Expressions를 사용할 때의 장단점이나 데이터 업데이트 주기에 대한 경험을 기록하세요.

## 4. 센서 제어 및 상보 필터링 (MPU6050 핵심)

### [개념 요약]
`HAL_I2C_Mem_Read/Write` 함수로 MPU6050 내부 레지스터에 접근하여 센서값을 얻었다. 가속도계의 단기적 노이즈와 자이로스코프의 장기적 오차 누적(드리프트) 현상을 상호 보완하기 위해 **상보 필터(Complementary Filter)**를 적용하여 Roll/Pitch 각도를 정밀하게 추정했다.

### [핵심 원리/공식]
- **16비트 데이터 병합:** MPU6050은 데이터를 8비트씩 나누어 (High byte, Low byte) 레지스터에 저장한다. 비트 시프트 연산(`<< 8`)과 비트 논리합(`|`)으로 하나의 16비트 정수(int16_t)로 합쳐야 한다.
- **가속도 기반 각도 계산:** 수학의 역삼각함수 **`atan2(y, x)`**를 사용해 각도를 계산한다. 라디안(Radian) 값을 디그리(Degree)로 변환하려면 `180 / PI`를 곱한다.
- **상보 필터 수식:**
  > $$ \text{Angle} = \alpha \times (\text{기존 각도} + \text{자이로 각속도} \times dt) + (1 - \alpha) \times \text{가속도계 각도} $$
  - $\alpha$는 보통 0.96 ~ 0.98의 가중치를 사용한다. (자이로스코프 비중을 높게, 가속도계 비중을 낮게)

### [구현 코드 스니펫]
```c
// 1. [뼈대 코드] MPU6050 Raw 데이터 읽기 및 병합
uint8_t raw_data[6];
int16_t accel_x_raw;

// HAL I2C 메모리 읽기 함수 파라미터 채우기 (hi2c1, Device Addr, Reg Addr, Size, Data, Len, Timeout)
HAL_I2C_Mem_Read(&hi2c1, _________, _________, I2C_MEMADD_SIZE_8BIT, raw_data, 6, 100);

// High Byte(raw_data[0])와 Low Byte(raw_data[1]) 합치기
accel_x_raw = (int16_t)(________________________);

// 2. [뼈대 코드] atan2를 이용한 각도 변환 (Pitch 예시)
// 가속도 x, y, z 성분을 사용하여 Pitch 각도를 구하는 공식 작성 (단위: Degree)
float pitch_acc = atan2(________, ________) * 180.0 / PI;

// 3. [뼈대 코드] 상보 필터 (Complementary Filter) 구현
float alpha = 0.96;
float dt = 0.01; // 루프 주기 (10ms)
float gyro_rate_pitch; // 자이로스코프 Pitch 축 회전 각속도
float filtered_pitch = 0.0;

// 상보 필터 핵심 수식 완성하기
filtered_pitch = alpha * (________________________) + (1.0 - alpha) * (______________);
```

### [나만의 필기 공간]
> $\alpha$ 값을 변경해 보면서 각도 출력 파형이 어떻게 변했는지, 혹은 atan2 함수 적용 시의 유의점 등을 기록하세요.

**[핵심 개념 보충: 드리프트 현상과 상보 필터의 원리]**

1. **드리프트(Drift) 현상이란?**
   - **자이로스코프의 한계**: 자이로스코프는 절대적인 각도가 아닌 '회전하는 속도(각속도)'를 측정함. 따라서 현재 각도를 구하려면 이전 각도에 각속도를 계속 더하는 '적분' 과정을 거쳐야 함.
   - **오차 누적**: 센서의 미세한 노이즈나 오프셋(가만히 있어도 0.01등의 값을 출력하는 현상)이 적분 과정을 통해 시간 단위로 계속 누적됨.
   - **결과**: 결국 센서가 정지해 있어도 계산된 각도가 한쪽으로 서서히 흘러가듯(Drift) 틀어지게 됨.

2. **상보 필터(Complementary Filter)의 원리**
   - **상보(相補)**: "서로 모자란 부분을 보충(보완)한다"는 의미. 자이로스코프의 장기적 오차(드리프트)와 가속도계의 단기적 오차(진동, 노이즈)를 상호 보완함.
   - **자이로스코프 (High-Pass Filter 역할)**: 수식에서 `α(약 0.96)`의 가중치를 두어 짧고 빠른 각도 변화를 민감하게 추적함.
   - **가속도계 (Low-Pass Filter 역할)**: 수식에서 `(1 - α)(약 0.04)`의 가중치를 두어, 덜컹거리는 노이즈는 무시하되 장기적으로 중력이라는 절대적인 기준점을 계속 더해줌.
   - **결론**: 자이로스코프로 빠른 움직임을 잡고, 가속도계로 방향을 지속적으로 교정하여 복잡한 행렬 연산(칼만 필터 등) 없이 단순한 가중치 수식만으로 빠르고 정확한 센서 융합을 이뤄냄.

## 5. 펌웨어 아키텍처 설계 (Bare-metal 리팩토링)

### [개념 요약]
초기 `main.c` 파일은 의도적으로 외부 라이브러리(HAL)나 표준 헤더(`<stdint.h>`) 없이 단일 파일에 모든 것이 포함된 **Self-contained Bare-metal** 구조로 작성되었다. 이는 메모리 주소(MMIO)에 직접 접근하여 하드웨어를 제어하는 원리를 밑바닥부터 이해하고, 스스로 모듈화를 연습하기 위한 뼈대 역할을 한다.

### [핵심 원리/공식]
- **Self-contained:** C 표준 라이브러리조차 사용하지 않고 자료형(`typedef`)부터 시작 코드(`Reset_Handler`) 및 벡터 테이블까지 모든 것을 직접 구현한 가장 독립적인 형태.
- **Bare-metal (MMIO):** OS나 하드웨어 추상화 계층(HAL/LL) 없이 주변장치의 물리적 메모리 주소(Register)에 직접 값을 쓰고 읽어(`*(volatile uint32_t *)`) 핀과 통신을 제어하는 원초적인 방식.
- **리팩토링 구조화:** 단일 파일로 뭉쳐진 코드를 `stm32f103_map.h`(레지스터 맵), `gpio.c`, `i2c.c` 등 모듈별로 분리해 나가며 확장성 있는 드라이버 아키텍처를 설계하는(쪼개는) 훈련을 거친다.

## 면접 답변 (30초 분량)

> `/easy-quiz` 실행 시 이 섹션이 정답 카드로 사용됩니다.

- **한 줄 정의:** 상보 필터는 가속도계의 노이즈와 자이로스코프의 드리프트 에러를 보완해 정확한 자세를 추정하는 센서 융합 알고리즘이다.
- **왜 필요:** 가속도계는 짧은 순간의 진동(노이즈)에 취약하고, 자이로스코프는 시간에 따라 오차가 누적되는 드리프트 현상이 발생하여 단일 센서만으로는 한계가 있기 때문이다.
- **동작:** 자이로스코프 데이터는 적분하여 하이패스 필터를 통과시키고, 가속도계 데이터는 로우패스 필터를 통과시킨 뒤 두 값을 가중치($\alpha$)를 두어 더해 최종 각도를 계산한다.
- **비교:** 칼만 필터(Kalman Filter)와 다르게 행렬 연산 없이 단순한 수식 하나로 구현이 가능하여, MCU의 연산 자원 소모가 적다는 차이가 있다.
- **30초 통합 답변:**
  > 상보 필터는 가속도계의 단기적 노이즈와 자이로스코프의 장기적 오차 누적(드리프트) 현상을 상호 보완하기 위한 가벼운 센서 융합 알고리즘입니다. 자이로스코프의 각도 변화량은 하이패스 필터로 누적시키고, 가속도계로 구한 절대 각도는 로우패스 필터로 걸러낸 후 두 값을 가중치로 합산합니다. 칼만 필터와 달리 연산량이 매우 적어 임베디드 환경(MCU)에서 실시간 자세 제어를 할 때 효율적입니다.

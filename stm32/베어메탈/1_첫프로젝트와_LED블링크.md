# STM32 베어메탈 #1 — 첫 프로젝트와 LED 블링크

**주제:** 최소 단위 프로젝트 구성 및 LED 블링크 (Hello World)
**타겟 MCU:** STM32F407
**원본 강의:** [STM32 Bare Metal Tutorial #1 (YouTube)](https://www.youtube.com/watch?v=m1C2LlFRwY4)

## 1. 핵심 개념: "베어메탈(Bare Metal)"이란?

일반적으로 OS(RTOS 등)를 사용하지 않는 환경을 베어메탈이라고 부르기도 하지만, 본 강의에서의 정의는 훨씬 엄격함.

- **정의:** 하드웨어와 코드 사이에 **어떠한 추상화 계층(Abstraction Layer)도 없는 상태**.
- **특징:** HAL(Hardware Abstraction Layer) 라이브러리를 일절 사용하지 않고, 오직 **레지스터(Register) 레벨에서 직접 하드웨어를 제어**함.

## 3. 실습 1: 최소 단위 프로젝트 (Minimal Project) 구축

STM32를 부팅시키고 코드를 실행하기 위한 **가장 완벽한 최소 조건(단 3개의 파일)**. 라이브러리나 어셈블리 파일 없이 C언어만으로 구성하는 것이 핵심.

### ① 링커 스크립트 (`.ld` 파일)

가장 하드웨어 종속적인 파일. 컴파일된 오브젝트 파일들을 메모리의 어디에 배치할지 결정함.

- **메모리 영역 정의:** Flash(코드 저장, 예: 512KB), RAM(데이터 저장, 예: 128KB)의 시작 주소와 크기 명시.
- **스택 포인터 (`_estack`):** RAM의 끝 주소(Origin + Length). 스택은 위에서 아래로 자라기 때문에 끝 주소를 시작점으로 잡음.
- **섹션 배치:** 텍스트(코드), 데이터, bss 영역 등의 메모리 매핑.

### ② 메인 코드 (`main.c`)

일반적으로 사용하는 어셈블리 스타트업 코드(`.s`)를 배제하고 **순수 C코드만으로 부트스트래핑(Bootstrapping)** 구현.

- **벡터 테이블 (Vector Table):** 플래시 메모리의 최상단 주소(`0x0800 0000`)에 위치.
  - 첫 번째 4바이트(Word): 스택 포인터 주소 (`_estack`)
  - 두 번째 4바이트: **Reset 핸들러 (부팅 시 실행될 함수의 포인터)**
- **Reset 함수:** 메모리 초기화 후 `main()` 함수를 호출. 절대로 종료되지 않도록 `__attribute__((naked))` 적용.
- **최적화 방지:** 컴파일러가 빈 코드를 삭제(Optimize out)하지 못하도록 `volatile` 변수(예: count)를 루프 안에서 연산.

### ③ 빌드 자동화 (`Makefile`)

- **옵션:** `-O0` (최적화 끄기 - 디버깅 및 동작 확인용).
- **프로세스:** 컴파일 → 링킹(`.elf` 생성) → 바이너리 추출(`.bin` 생성).
- 이 3개의 파일만으로 컴파일 시 불과 **약 500바이트** 수준의 초경량 펌웨어 완성!

## 4. 실습 2: LED 블링크 (진정한 Hello World)

단순 무한 루프를 넘어, 실제로 하드웨어(LED)를 제어하기 위한 필수 단계.

### 주의사항: 클럭(Clock)의 이해

> **주의**
> - STM32는 부팅 직후 내부 RC 오실레이터에 의해 **16MHz**로 동작함.
> - **전력 소모를 막기 위해 모든 주변장치(Peripheral)의 클럭은 기본적으로 꺼져 있음(Unclocked).**
> - 따라서 GPIO를 제어하려면 반드시 **해당 GPIO 포트에 클럭을 먼저 공급**해야 함.

### 동작 순서 (제어 파이프라인)

1. **RCC (Reset and Clock Control) 설정:**
   - 레지스터 구조체를 매핑하여 핀이 연결된 GPIO 포트(예: Port C)의 클럭 활성화.
2. **GPIO 모드 설정 (Output):**
   - GPIOx_MODER 레지스터를 건드려 해당 핀(예: C13)을 출력 모드(Output Mode)로 변경.
3. **핀 상태 토글 (BSRR 레지스터):**
   - `BSRR (Bit Set/Reset Register)`는 32비트 레지스터.
   - 하위 16비트에 1을 쓰면 -> 핀 **SET** (High)
   - 상위 16비트에 1을 쓰면 -> 핀 **RESET** (Low)
4. **딜레이 함수 적용 (Spin):**
   - 16MHz 클럭 속도에 맞춰 단순 카운트다운 루프를 돌려 시각적으로 깜빡임을 인지할 수 있는 시간 지연(Delay) 생성.

## 5. 인사이트 & 노트 포인트

> **예외**
> 일반 강의에서는 잘 다루지 않는 베어메탈 특유의 관점.

- **어셈블리 없는 부팅의 우아함:** 보통 STM32 CubeIDE가 자동 생성해 주는 복잡한 `.s` 파일 없이, 구조체 배열 형태의 C 코드로 벡터 테이블을 짜는 기법은 코드 가독성을 극대화함.
- **구조체 매핑의 마법:** 특정 메모리 주소(예: `0x40023800`)를 포인터로 강제 캐스팅한 뒤, 멤버 변수 오프셋을 통해 레지스터에 접근하는 방식은 베어메탈 C 프로그래밍의 정수임.
- **최적화 챌린지:** 완성된 기본 블링크 바이너리는 약 784바이트. 변수 초기화나 규정을 무시하는 등 "편법"을 동원하면 150바이트 이하로도 줄일 수 있음. 하드웨어의 극한을 이해하는 좋은 훈련이 됨.

## 면접 답변 (30초 분량)

> `/easy-quiz` 실행 시 이 섹션이 정답 카드로 사용됩니다.

- **한 줄 정의:** 베어메탈은 HAL·OS 같은 추상화 계층 없이 **레지스터 레벨에서 직접 하드웨어를 제어**하는 프로그래밍 방식이다.
- **왜 필요:** 코드 크기·실행 속도·전력 소모를 극한으로 최적화하고, 하드웨어 동작을 완전히 이해·제어해야 하는 임베디드 환경에서 필요.
- **동작:** 링커 스크립트로 Flash/RAM 배치, 벡터 테이블 첫 워드에 스택 포인터·둘째 워드에 Reset 핸들러를 둔다. Reset에서 메모리 초기화 후 `main` 호출, RCC로 주변장치 클럭을 켜고 레지스터를 직접 써서 제어한다.
- **비교:** HAL 라이브러리 방식과 다르게 추상화 오버헤드가 없어 펌웨어가 500바이트 수준으로 작지만, 레지스터·메모리 맵을 직접 다뤄야 해 Reference Manual 의존도가 높다.
- **30초 통합 답변:**
  > 베어메탈은 HAL이나 OS 같은 추상화 계층 없이 레지스터를 직접 제어하는 방식입니다. 링커 스크립트로 Flash·RAM을 배치하고, 벡터 테이블 첫 워드에 스택 포인터, 둘째 워드에 Reset 핸들러를 두어 순수 C만으로 부팅합니다. STM32는 부팅 시 주변장치 클럭이 꺼져 있어 RCC로 GPIO 포트 클럭을 켠 뒤 MODER로 출력 모드를 설정하고 BSRR로 핀을 토글합니다. HAL 방식과 달리 펌웨어가 500바이트 수준으로 작고 하드웨어를 완전히 이해·제어할 수 있다는 장점이 있습니다.

# STM32 입문 #8 — 타이머/카운터와 PWM

**주제:** 타이머와 카운터의 차이, 업/업다운 카운트, ARR·CCR로 PWM 만들기, 상보 출력과 데드타임, 반복 카운터(RCR), 1초 주기 LED 토글 실습
**타겟 MCU:** STM32F767VIT6
**원본 강의:** [(210) STM32 입문 강의 몰아보기 | ARM, GPIO, ADC, UART (YouTube)](https://www.youtube.com/watch?v=XOsyrZGZtR8)

> 타이머는 PWM 생성의 핵심이다. 삼상 인버터로 BLDC 모터를 구동하려면 **상보 PWM + 데드타임**이 필수다.

---

## 1. 타이머 vs 카운터

하나의 모듈(Timer/Counter)에 두 기능이 합쳐져 있다. 차이는 **내부 클럭 사용 여부**.

- **타이머(Timer)** — **내부 클럭**으로 일정 주기 신호를 만들거나 시간을 측정. PWM 생성에 핵심.
- **카운터(Counter)** — **외부 신호**를 계수(counting).

---

## 2. 동작 원리 — Prescaler · ARR · CCR

타이머도 주변 장치라 클럭으로 동작한다. 흐름:

1. 클럭 → **Prescaler**로 원하는 주파수로 분주.
2. 그 클럭에 동기화해 **0, 1, 2, 3…** 카운트. 하나 셀 때 걸리는 시간 = 클럭 주기(주파수의 역수).
3. **ARR (Auto-Reload Register)** — 카운터의 **최댓값**. 예: ARR=100이면 0~100까지 센다.
4. **CCR (Capture/Compare Register)** — 카운터 값과 **비교**해 특정 시점에 출력을 ON/OFF. 이때 토글되는 핀이 **OC(Output Compare) 레퍼런스**.

---

## 3. 카운트 모드

### 3.1 업카운트(Up Count)

0부터 위로 센다. ARR에 도달하면 **오버플로우** 발생 → 0으로 떨어짐 → **Update Event** 발생(인터럽트 가능) → 반복.

예: ARR=4 → 0,1,2,3,4(오버플로우)→0…

### 3.2 업다운카운트 = 센터 얼라인(Center Aligned)

0→ARR로 올라갔다 ARR→0로 내려옴. **올라갈 때 오버플로우, 내려와 0에서 언더플로우** 이벤트가 각각 발생.

예: ARR=6 → 0…6(오버플로우)→…0(언더플로우)→반복.

> **이미지 필요**
> 업카운트 vs 센터얼라인 카운터 파형 + Update Event 시점
> - 출처: 강의 슬라이드 2:35~2:37
> - 대체안: 레퍼런스 매뉴얼 타이머 카운팅 모드 그림

---

## 4. PWM 생성 — ARR과 CCR의 조합

### 4.1 단일 채널 (업카운트)

ARR=4, CCR=3 예시:
- 카운터 0부터 증가, **CCR(3)과 같아지는 순간 OC 출력 Low**.
- ARR(4) 도달 → 0으로 리셋되며 **출력 High**.
- 무한 반복 → PWM 파형 완성.

**듀티 조절 = CCR 조절.** CCR을 키우면 ON 시간(켜져 있는 구간)이 늘어 듀티비가 커진다. (극성 설정에 따라 반대로 뒤집을 수도 있음.)

### 4.2 다채널 PWM

여러 CCR(CCR1, CCR2…)을 각각 두면 한 카운터로 여러 출력 신호를 동시에 제어할 수 있다. 16비트 타이머는 0~65535(2¹⁶)까지 세어 분해능이 높다.

### 4.3 PWM 모드 1 vs 2 와 극성

- **PWM 모드 1** — 카운터 > CCR이면 inactive, < CCR이면 active.
- **중요:** **active = 무조건 High가 아니다.** active가 High인지 Low인지는 **`CCER` 레지스터**에서 따로 정의한다.
  - Active High 설정 → active일 때 3.3V.
  - Active Low 설정 → active일 때 0V.
- `CCER`로 **PWM 극성을 자유롭게** 바꿀 수 있다.

---

## 5. ARR 프리로드(ARPE) — 글리치 방지

타이머 컨트롤 레지스터 1(`CR1`)의 **ARPE(Auto-Reload Preload Enable)** 비트.

> **주의 — 동작 중 ARR 변경의 위험.**
> 카운터가 7까지 센 상태에서 ARR을 10→5로 바꾸면:
> - **ARPE=0:** 즉시 적용 → 현재 7인데 5로 줄면 비정상적인 짧은 펄스(**글리치**) 발생.
> - **ARPE=1:** 일단 10까지 세고 **다음 Update Event(0으로 떨어질 때)** 에 5를 적용 → 부드러운 전환.

글리치는 원치 않는 짧은 펄스/일시적 오류 신호다. PWM 한 주기가 끝나기 전 ARR을 바꾸면 비정상 폭의 펄스가 생긴다. **웬만하면 ARPE=1**로 쓴다.

---

## 6. 고급 타이머 — 상보 출력과 데드타임

F767은 타이머 1~14(14개)를 갖는다. 그중 **타이머 1·8은 고성능 타이머**로 **모터 제어에 최적화**돼 있다.

### 6.1 상보 출력 (Complementary)

타이머 1·8은 PWM 채널을 **반전 출력**할 수 있다. 즉 **상보 동작 자동 지원**.
- 채널 1 출력과 채널 1N 출력이 **서로 반대**로 나간다.

> **왜 필요한가 — Arm-short 방지.**
> 삼상 인버터의 한 상에는 위·아래 스위치 2개가 있다. **둘 다 동시에 ON되면 단락(Arm-short)** 으로 큰 전류가 흘러 망가진다. 그래서 하나가 ON이면 하나는 OFF가 되도록 **상보로 번갈아** 구동해야 한다. 타이머 1·8이 이를 자동 설정해 준다.

### 6.2 데드타임 (Dead Time)

> **주의 — 상보만으로 부족하다.**
> 각 스위치는 켜지고 꺼지는 데 시간 차가 있다. 위 스위치가 완전히 꺼지기 전에 아래가 켜지면 순간적으로 둘 다 ON될 수 있다. 이를 막으려고 상보 신호 사이에 **데드타임**(둘 다 OFF인 짧은 지연)을 넣는다.

타이머 1은 채널 1~3에 한 상의 상보 신호를 출력하고 데드타임을 설정할 수 있다. BLDC·PMSM 같은 3상 모터 구동에 **상보 PWM + 데드타임은 필수**. (전동 킥보드 펌웨어에서 적용 예정.)

### 6.3 반복 카운터 (RCR)

타이머 1·8의 **RCR(Repetition Counter Register)**: 지정 횟수만큼 카운트를 반복한 뒤에야 Update Event를 발생시킨다.
- 업카운트면 오버플로우마다, 다운카운트면 언더플로우마다 RCR이 1씩 감소.
- 센터얼라인 + RCR 홀수면 오버플로우 또는 언더플로우 한쪽에서만 동작 → **Update Event 발생 위치를 자유롭게** 제어. (카운터 시작 전 RCR 설정 시 오버플로우, 시작 후 설정 시 언더플로우에서만.)

## 7. 실습 — 1초 주기 LED 토글

타이머로 **1초마다 오버플로우**를 만들어 PD3 LED를 토글한다.

### 7.1 주기 계산

- 시스템 클럭(AHB) = 216MHz. 타이머 클럭도 216MHz(클럭 편의 `DCKCFGR1` TIMPRE=1 덕분).
- **Prescaler로 216MHz → 10kHz**: 216,000,000 ÷ 21,600 = 10,000Hz.
  - 코드에선 `PSC = 21600 - 1` (0부터 시작하므로 −1).
- 10kHz면 1카운트 = 0.0001초. **1초 = 10,000 카운트** → **ARR = 10000**.

```
주기 = (PSC+1) × (ARR+1) / f_clk
     = 21600 × 10000 / 216,000,000 = 1초
```

### 7.2 설정 순서

1. **`init_MCU()`**, LED(PD3) 출력 설정.
2. **타이머 클럭 enable** — 타이머 1은 **APB2**. `RCC_APB2ENR`로 enable. (DCKCFGR1 설정으로 타이머 클럭 216MHz 보장 — 데이터시트에 작게 숨겨진 조건.)
3. **`TIM_PSC`** = 21600−1 (10kHz로 분주).
4. **`TIM_ARR`** = 10000 (1초 주기).
5. **`TIM_EGR`** 의 UG 비트=1 → Update Generation, 즉시 로드해 타이머 적용.
6. **`TIM_DIER`** 의 UIE 비트=1 → Update Interrupt enable.
7. **`NVIC_EnableIRQ(TIM1_UP_TIM10_IRQn)`** — 벡터 테이블 25번(우선순위 디폴트 32). 타이머1 업데이트 인터럽트.
8. **`TIM_CR1`** 의 CEN 비트=1 → 카운터 enable. 이후 `while(1)`은 **비움**(처리는 ISR에서).

### 7.3 ISR

```c
void TIM1_UP_TIM10_IRQHandler(void) {
    if (TIM1->SR & (1 << 0)) {        // UIF: Update Interrupt Flag
        TIM1->SR &= ~(1 << 0);        // 플래그 클리어 (다음 인터럽트 위해)
        GPIOD->ODR ^= (1 << 3);       // LED 토글
    }
}
```

- `SR`의 **UIF(Update Interrupt Flag)** 로 발생 확인.
- 플래그를 **0으로 클리어**해야 다음 인터럽트를 구분.
- LED를 XOR 토글 → **1초마다 켜졌다 꺼졌다** 반복.

## 면접 답변 (30초 분량)

> `/easy-quiz` 실행 시 이 섹션이 정답 카드로 사용됩니다.

- **한 줄 정의:** 타이머는 내부 클럭으로 카운트해 주기 신호·PWM을 만드는 모듈이고, ARR로 최댓값, CCR로 비교 시점을 정한다.
- **왜 필요:** 정확한 시간 주기 생성, 모터 제어용 PWM 생성에 필수다.
- **동작:** Prescaler로 분주한 클럭으로 카운트하다 ARR에서 오버플로우(Update Event). CCR과 카운터를 비교해 OC 출력을 토글하면 PWM이 되고, CCR 크기로 듀티를 조절한다. 주기 = (PSC+1)(ARR+1)/f.
- **비교:** 업카운트는 한 방향, 센터얼라인은 업다운. 타이머 1·8은 상보 출력과 데드타임을 지원해 인버터 Arm-short를 막는다. ARPE=1이면 ARR 변경이 다음 Update에 적용돼 글리치를 방지한다.
- **30초 통합 답변:**
  > 타이머는 내부 클럭을 프리스케일러로 분주한 뒤 카운트하는 모듈입니다. ARR이 카운터 최댓값이라 거기 도달하면 오버플로우가 나며 Update Event가 발생하고, CCR과 카운터를 비교해 출력을 토글하면 PWM이 만들어집니다. CCR을 키우면 듀티가 커지고, 극성은 CCER로 정합니다. 제 실습에선 216MHz를 21600분주해 10kHz로 만들고 ARR을 10000으로 둬서 1초 주기를 만든 뒤, Update 인터럽트 핸들러에서 LED를 XOR로 토글했습니다. 모터 제어에선 타이머 1·8의 상보 출력으로 인버터 상하 스위치를 번갈아 켜 Arm-short를 막고, 스위칭 시간 차로 둘 다 켜지는 걸 방지하려고 데드타임을 넣습니다. ARR을 동작 중 바꿀 땐 ARPE를 1로 둬서 다음 Update에 반영되게 해 글리치를 방지합니다.

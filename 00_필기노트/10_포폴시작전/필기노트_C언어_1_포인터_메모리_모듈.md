<span style="color:#1d4ed8">I. C언어 심화 1 — 포인터·메모리·모듈</span><br>
<br>
<span style="color:#1d4ed8">1. 포인터는 주소를 타입과 함께 다루는 방법</span><br>
<span style="color:#1d4ed8">1) 용어 설명</span><br>
<span style="color:#111827">① <strong>메모리</strong>(memory): byte 단위 칸들이 이어진 저장 공간</span><br>
<span style="color:#111827">② <strong>주소</strong>(address): 메모리 칸이 있는 위치를 가리키는 번호</span><br>
<span style="color:#111827">③ <strong>포인터</strong>(pointer): 어떤 객체의 주소를 저장해 그 위치에 접근하는 변수</span><br>
<span style="color:#dc2626">! <strong>주소를 들고 → 타입에 맞게 읽고 → 원본 객체에 접근</strong>한다고 먼저 잡기</span><br>
<br>
<span style="color:#1d4ed8">2) 메모리와 주소</span><br>
<span style="color:#111827">① 메모리는 byte 단위 칸의 집합이고 각 칸에 주소가 있음</span><br>
<span style="color:#111827">a. 타입은 <strong>몇 byte를 읽을지와 bit를 어떻게 해석할지</strong>를 정함</span><br>
<span style="color:#111827">b. 포인터는 값이 아니라 어떤 객체가 있는 주소를 저장하는 변수</span><br>
<span style="color:#111827">cf) int*, uint8_t*, struct Packet*는 주소 크기와 별개로 대상 해석이 다름</span><br>
<span style="color:#111827">→ <strong>struct Packet *p</strong>는 Packet 구조체 한 개가 있는 주소를 저장하며, <strong>*p</strong>는 그 구조체 자체임</span><br>
<span style="color:#111827">→ <strong>p-&gt;field</strong>로 구조체 멤버에 접근하고, p + 1은 Packet 한 개 크기만큼 이동함</span><br>
<span style="color:#dc2626">! <strong>포인터 크기는 대상 크기가 아니라 target의 주소 크기</strong>에 따라 달라짐</span><br>
<br>
<span style="color:#1d4ed8">3) &와 * 연산자</span><br>
<span style="color:#111827">① <strong>&amp;value</strong> = value가 저장된 주소</span><br>
<span style="color:#111827">② <strong>*p</strong> = p가 가리키는 주소의 실제 객체</span><br>
<span style="color:#111827">a. C는 인자를 값으로 복사해서 전달함</span><br>
<span style="color:#111827">b. 원본을 바꾸려면 주소를 넘기고 함수 안에서 *p로 접근</span><br>
<span style="color:#dc2626">! <strong>유효하지 않은 주소·NULL을 역참조하면 undefined behavior</strong></span><br>
<br>
<span style="color:#1d4ed8">ex) 원본 값 바꾸기</span><br>
<span style="color:#111827">void set_led(uint32_t *state) { *state = 1U; }</span><br>
<span style="color:#111827">uint32_t led = 0U;  set_led(&led);</span><br>
<span style="color:#111827">→ led 값 자체가 1U로 바뀜</span><br>
<br>
<span style="color:#1d4ed8">4) 포인터 연산과 배열</span><br>
<span style="color:#111827">① <strong>p + 1은 1 byte가 아니라 sizeof(*p)만큼</strong> 다음 객체로 이동</span><br>
<span style="color:#111827">② <strong>arr[i]는 *(arr + i)</strong>와 같은 뜻</span><br>
<span style="color:#111827">③ 배열 이름은 대부분 식에서 첫 원소 포인터로 변환(decay)됨</span><br>
<span style="color:#dc2626">! <strong>배열과 포인터는 같은 것이 아님</strong>: 배열은 크기·저장 공간을 가진 객체</span><br>
<br>
<span style="color:#1d4ed8">2. 배열 경계와 함수 호출 규칙</span><br>
<span style="color:#1d4ed8">1) 배열 decay의 예외</span><br>
<span style="color:#111827">① sizeof arr: 배열 전체 byte 수</span><br>
<span style="color:#111827">② &arr: 첫 원소 주소가 아니라 배열 전체를 가리키는 주소</span><br>
<span style="color:#111827">③ 함수 매개변수의 arr는 이미 포인터처럼 다뤄짐</span><br>
<span style="color:#111827">a. 따라서 함수 안에서 sizeof(arr)로 원래 배열 길이를 구할 수 없음</span><br>
<span style="color:#dc2626">! buffer API에는 <strong>포인터와 길이(size_t)를 반드시 함께 전달</strong></span><br>
<br>
<span style="color:#1d4ed8">2) const 포인터 읽는 법</span><br>
<span style="color:#111827">① T를 임의의 타입이라고 할 때, <strong>const T *p</strong>: p가 가리키는 대상은 p를 통해 수정할 수 없고, p는 다른 주소를 가리키도록 바꿀 수 있음</span><br>
<span style="color:#111827">② <strong>T *const p</strong>: p가 가리키는 주소는 바꿀 수 없고, 대상 값은 p를 통해 수정할 수 있음</span><br>
<span style="color:#111827">③ <strong>const T *const p</strong>: p가 가리키는 주소도, p를 통한 대상 수정도 모두 불가</span><br>
<span style="color:#111827">a. <strong>void process(const T *buf, size_t len)</strong>은 함수가 buf를 통해 입력 데이터를 수정하지 않는다는 계약</span><br>
<span style="color:#dc2626">! <strong>const는 객체가 절대 안 변한다는 뜻이 아니라 이 접근 경로의 쓰기를 막음</strong></span><br>

<br>
<span style="color:#1d4ed8">3) sizeof의 기준</span><br>
<span style="color:#111827">① sizeof는 식 또는 타입의 byte 수를 size_t로 반환</span><br>
<span style="color:#111827">② <strong>sizeof arr / sizeof arr[0]</strong> = 배열 원소 개수</span><br>
<span style="color:#111827">③ <strong>sizeof p</strong> = 포인터 변수의 크기</span><br>
<span style="color:#111827">④ <strong>sizeof *p</strong> = p가 가리키는 타입 한 개의 크기</span><br>
<span style="color:#dc2626">! <strong>malloc(200) 뒤 sizeof p는 200이 아니라 포인터 크기</strong></span><br>
<br>
<span style="color:#1d4ed8">ex) 길이를 같이 전달</span><br>
<span style="color:#111827">void send(const uint8_t *data, size_t len);</span><br>
<span style="color:#111827">size_t used = 200U;  send(buf, used);</span><br>
<span style="color:#111827">할당 용량, 실제 유효 길이, 목적지 용량은 서로 다를 수 있음</span><br>
<br>
<span style="color:#1d4ed8">4) 함수 포인터와 callback</span><br>
<span style="color:#111827">① 함수 이름은 대부분 식에서 함수 시작 주소로 사용됨</span><br>
<span style="color:#111827">② void (*action)(void): 인자 없고 void 반환인 함수를 가리킴</span><br>
<span style="color:#111827">③ action() 또는 (*action)()으로 간접 호출</span><br>
<span style="color:#111827">④ <strong>callback</strong>은 호출 시점은 공통으로 두고 동작만 호출자가 넘기는 구조</span><br>
<span style="color:#111827">a. event handler, driver abstraction, 정렬 비교 함수에 사용</span><br>
<span style="color:#dc2626">! 대상 함수와 함수 포인터의 인자·반환 타입이 다르면 cast로 숨기지 말 것</span><br>
<br>
<span style="color:#1d4ed8">ex) callback 뼈대</span><br>
<span style="color:#111827">typedef void (*Callback)(void);</span><br>
<span style="color:#111827">void run_when_ready(Callback cb) { cb(); }</span><br>
<span style="color:#111827">→ run_when_ready는 언제 실행할지, caller는 무엇을 할지 결정</span><br>
<br>
<span style="color:#1d4ed8">3. 객체의 수명과 동적 할당</span><br>
<span style="color:#1d4ed8">1) 용어 설명</span><br>
<span style="color:#111827">① <strong>stack</strong>: 함수 호출과 함께 만들어지고 반환하면 자동으로 사라지는 영역</span><br>
<span style="color:#111827">② <strong>heap</strong>: malloc으로 요청하고 free 전까지 유지되는 동적 영역</span><br>
<span style="color:#111827">③ <strong>static storage</strong>: 프로그램 시작부터 종료까지 유지되는 전역/static 객체 영역</span><br>
<span style="color:#dc2626">! <strong>누가 만들고 → 언제까지 살며 → 누가 해제하는지</strong>를 함께 확인</span><br>
<br>
<span style="color:#1d4ed8">2) C 프로그램 메모리 레이아웃</span><br>
<span style="color:#111827">① .text: 기계어 코드, 보통 Flash/ROM에 저장</span><br>
<span style="color:#111827">② .data: 초기값 있는 전역/static, 초기값 이미지는 Flash에도 존재</span><br>
<span style="color:#111827">③ .bss: 초기값 없는 전역/static, 시작 시 0으로 초기화</span><br>
<span style="color:#111827">④ stack: 지역 변수·함수 호출 정보, 호출/반환에 따라 자동 관리</span><br>
<span style="color:#111827">⑤ heap: malloc으로 얻는 동적 block, free 전까지 유지</span><br>
<span style="color:#dc2626">! MCU는 RAM이 작으므로 stack·전역·heap 사용량을 함께 예측해야 함</span><br>
<br>
<span style="color:#1d4ed8">그림: 수명으로 구분</span><br>
<span style="color:#111827">함수 호출 → stack frame 생성 → return → 자동 해제</span><br>
<span style="color:#111827">malloc → heap block 생성 → free → 해제</span><br>
<span style="color:#111827">전역/static → 프로그램 시작부터 종료까지 유지</span><br>
<span style="color:#dc2626">! 포인터가 사라져도 heap block은 자동 해제되지 않음</span><br>
<br>
<span style="color:#1d4ed8">3) malloc 사용 원칙</span><br>
<span style="color:#111827">① 필요한 크기가 실행 중에 결정될 때 사용</span><br>
<span style="color:#111827">② 반환값이 NULL인지 확인</span><br>
<span style="color:#111827">③ 소유자와 free 책임을 API 설계에서 명확히 정함</span><br>
<span style="color:#111827">④ free 뒤 포인터를 다시 쓰지 않고, 가능하면 NULL 대입</span><br>
<span style="color:#dc2626">! <strong>leak, double free, use-after-free는 치명적인 메모리 오류</strong></span><br>
<br>
<span style="color:#1d4ed8">4) 실시간 시스템에서의 선택</span><br>
<span style="color:#111827">① 일반 malloc/free는 실행 시간 변동과 heap fragmentation을 만들 수 있음</span><br>
<span style="color:#111827">② ISR 안에서는 할당하지 않음</span><br>
<span style="color:#111827">③ 가능하면 정적 버퍼, stack, 고정 블록 pool을 사용</span><br>
<span style="color:#111827">④ 꼭 동적 할당하면 초기화 단계에 한 번 할당하고 실패 경로도 검증</span><br>
<span style="color:#dc2626">! <strong>실시간성은 평균 속도가 아니라 최악 실행 시간의 예측 가능성</strong></span><br>
<br>
<span style="color:#1d4ed8">4. static과 선언·정의로 모듈 경계를 만든다</span><br>
<span style="color:#1d4ed8">1) static은 위치에 따라 뜻이 다름</span><br>
<span style="color:#111827">① <strong>함수 지역 static</strong>: 이름은 함수 안, 객체 수명은 프로그램 전체</span><br>
<span style="color:#111827">② <strong>파일 범위 static 변수/함수</strong>: 이 .c 파일에서만 보이는 internal linkage</span><br>
<span style="color:#111827">③ 모듈 내부 state와 helper 함수는 static으로 숨기고 API만 공개</span><br>
<span style="color:#dc2626">! 지역 static은 숨은 공유 상태라 ISR/스레드 재진입 안전성을 따로 검토</span><br>
<br>
<span style="color:#1d4ed8">2) 선언과 정의</span><br>
<span style="color:#111827">① <strong>선언</strong>: 이름·타입을 알림, extern int ticks;</span><br>
<span style="color:#111827">② <strong>정의</strong>: 실제 저장 공간/함수 본문 하나를 만듦, int ticks = 0;</span><br>
<span style="color:#111827">③ 초기화된 extern은 선언이 아니라 정의</span><br>
<span style="color:#111827">④ 공유 전역은 header에 extern 선언, 한 .c에만 정의</span><br>
<span style="color:#dc2626">! header에 전역 변수 정의를 넣으면 <strong>multiple definition 위험</strong></span><br>
<br>
<span style="color:#1d4ed8">3) .h / .c / linker</span><br>
<span style="color:#111827">① 각 .c와 include 결과는 translation unit</span><br>
<span style="color:#111827">② compiler: .c → .o, linker: 여러 .o와 library를 연결</span><br>
<span style="color:#111827">③ .h에는 공개 선언·타입·매크로, .c에는 실제 구현</span><br>
<span style="color:#111827">④ include guard로 같은 header의 중복 포함을 방지</span><br>
<span style="color:#111827">cf) #include는 텍스트 삽입, link는 object file 결합</span><br>
<span style="color:#dc2626">! undefined reference는 구현 object/library가 link에 빠졌는지 먼저 확인</span><br>
<br>
<span style="color:#1d4ed8">5. 핵심 3줄</span><br>
<span style="color:#111827">1) <strong>포인터는 주소를 타입과 함께 다루며, 원본 객체에 접근할 때는 유효한 주소와 대상 타입을 함께 확인한다.</strong></span><br>
<span style="color:#111827">2) <strong>배열은 포인터로 decay할 수 있지만 크기를 가진 객체이므로, 함수에는 포인터와 길이를 함께 전달한다.</strong></span><br>
<span style="color:#111827">3) <strong>임베디드에서는 객체 수명과 최악 실행 시간을 고려해 stack·정적 메모리를 우선하고, 모듈 내부는 static으로 숨긴다.</strong></span><br>
<br>
<span style="color:#1d4ed8">Q. 배열과 포인터가 다른 이유는?</span><br>
<span style="color:#111827">A. 배열은 크기와 저장 공간을 가진 객체이고, 배열 이름은 대부분의 식에서 첫 원소 포인터로 변환될 뿐이다.</span><br>
<span style="color:#1d4ed8">Q. sizeof p와 sizeof *p의 차이는?</span><br>
<span style="color:#111827">A. sizeof p는 포인터 변수의 주소 크기이고, sizeof *p는 포인터가 가리키는 타입 한 개의 크기다.</span><br>
<span style="color:#1d4ed8">Q. ISR에서 malloc을 피하는 이유는?</span><br>
<span style="color:#111827">A. malloc/free는 실행 시간 변동과 heap fragmentation을 만들 수 있어 ISR 응답 시간의 예측 가능성을 해친다.</span><br>
<span style="color:#1d4ed8">Q. static 지역 변수는 왜 재진입에 주의해야 하나?</span><br>
<span style="color:#111827">A. 함수 호출마다 새로 만들어지지 않는 숨은 공유 상태이므로 ISR이나 스레드가 동시에 접근하면 안전성을 따로 검토해야 한다.</span><br>
<span style="color:#1d4ed8">Q. #include만 했는데 undefined reference가 나는 이유는?</span><br>
<span style="color:#111827">A. #include는 선언을 텍스트로 삽입할 뿐이므로, 실제 구현 object file이나 library가 link에 빠지면 오류가 난다.</span><br>
<br>
<span style="color:#1d4ed8">6. 30초 면접 답변</span><br>
<span style="color:#111827">C에서 포인터는 메모리 주소를 타입과 함께 다루는 변수로, 배열 순회나 함수에서 원본 데이터 접근, 그리고 MCU 레지스터 접근의 기반이 됩니다.</span><br>
<span style="color:#111827">배열은 포인터로 변환될 수 있지만 자체 크기를 가진 객체이므로, 버퍼 API에는 포인터와 길이를 함께 전달해야 합니다. 특히 sizeof 포인터는 동적 메모리 크기가 아니라 주소 크기입니다.</span><br>
<span style="color:#111827">임베디드에서는 stack과 정적 메모리를 우선하고, 동적 할당은 시간 변동과 단편화를 고려해 제한합니다.</span><br>
<span style="color:#dc2626">모듈은 header의 선언과 .c의 단일 정의로 나누고, 내부 상태는 static으로 숨기는 방식이 안전합니다.</span><br>
<br>

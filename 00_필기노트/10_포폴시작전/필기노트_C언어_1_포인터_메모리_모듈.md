# C언어 심화 1 — 포인터·메모리·모듈

용도: A4 세로 반 접기 2열 손필기

규칙:

- 1열 32줄 기준
- 내용이 길면 다음 페이지로 넘김
- 들여쓰기 없음
- 파랑: 제목, 번호, 핵심 키워드
- 검정: 설명, 예시, cf
- 빨강: 면접 주의, 헷갈리는 점

## 1페이지: 주소·포인터·배열

<span style="color:#1d4ed8">주제: 포인터는 주소를 타입과 함께 다루는 방법</span><br>
<span style="color:#1d4ed8">1. 메모리와 주소</span><br>
<span style="color:#111827">a. 메모리는 byte 단위 칸의 집합이고 각 칸에 주소가 있음</span><br>
<span style="color:#111827">b. 타입은 몇 byte를 읽을지와 bit를 어떻게 해석할지를 정함</span><br>
<span style="color:#111827">c. 포인터는 값이 아니라 어떤 객체가 있는 주소를 저장하는 변수</span><br>
<span style="color:#111827">cf) int*, uint8_t*, struct Packet*는 주소 크기와 별개로 대상 해석이 다름</span><br>
<span style="color:#dc2626">※ 포인터 크기는 대상 크기가 아니라 target의 주소 크기에 따라 달라짐</span><br>
<br>
<span style="color:#1d4ed8">2. &와 * 연산자</span><br>
<span style="color:#111827">a. &value = value가 저장된 주소</span><br>
<span style="color:#111827">b. *p = p가 가리키는 주소의 실제 객체</span><br>
<span style="color:#111827">c. C는 인자를 값으로 복사해서 전달함</span><br>
<span style="color:#111827">- 원본을 바꾸려면 주소를 넘기고 함수 안에서 *p로 접근</span><br>
<span style="color:#dc2626">※ 유효하지 않은 주소·NULL을 역참조하면 undefined behavior</span><br>
<br>
<span style="color:#1d4ed8">예: 원본 값 바꾸기</span><br>
<span style="color:#111827">void set_led(uint32_t *state) { *state = 1U; }</span><br>
<span style="color:#111827">uint32_t led = 0U;  set_led(&led);</span><br>
<span style="color:#111827">→ led 값 자체가 1U로 바뀜</span><br>
<br>
<span style="color:#1d4ed8">3. 포인터 연산과 배열</span><br>
<span style="color:#111827">a. p + 1은 1 byte가 아니라 sizeof(*p)만큼 다음 객체로 이동</span><br>
<span style="color:#111827">b. arr[i]는 *(arr + i)와 같은 뜻</span><br>
<span style="color:#111827">c. 배열 이름은 대부분 식에서 첫 원소 포인터로 변환(decay)됨</span><br>
<span style="color:#dc2626">※ 배열과 포인터는 같은 것이 아님: 배열은 크기·저장 공간을 가진 객체</span><br>
<br>
<span style="color:#1d4ed8">4. 배열 decay의 예외</span><br>
<span style="color:#111827">a. sizeof arr: 배열 전체 byte 수</span><br>
<span style="color:#111827">b. &arr: 첫 원소 주소가 아니라 배열 전체를 가리키는 주소</span><br>
<span style="color:#111827">c. 함수 매개변수의 arr는 이미 포인터처럼 다뤄짐</span><br>
<span style="color:#111827">- 따라서 함수 안에서 sizeof(arr)로 원래 배열 길이를 구할 수 없음</span><br>
<span style="color:#dc2626">※ buffer API에는 포인터와 길이(size_t)를 반드시 함께 전달</span><br>

## 2페이지: const·sizeof·함수 포인터

<span style="color:#1d4ed8">5. const 포인터 읽는 법</span><br>
<span style="color:#111827">a. const uint8_t *p: *p는 수정 불가, p는 다른 주소로 이동 가능</span><br>
<span style="color:#111827">b. uint8_t *const p: p 주소는 고정, *p 값은 수정 가능</span><br>
<span style="color:#111827">c. const uint8_t *const p: 주소와 대상 모두 수정 불가</span><br>
<span style="color:#111827">- uart_send(const uint8_t *buf, size_t len)는 입력 버퍼를 안 바꾼다는 계약</span><br>
<span style="color:#dc2626">※ const는 객체가 절대 안 변한다는 뜻이 아니라 이 접근 경로의 쓰기를 막음</span><br>
<br>
<span style="color:#1d4ed8">6. sizeof의 기준</span><br>
<span style="color:#111827">a. sizeof는 식 또는 타입의 byte 수를 size_t로 반환</span><br>
<span style="color:#111827">b. sizeof arr / sizeof arr[0] = 배열 원소 개수</span><br>
<span style="color:#111827">c. sizeof p = 포인터 변수의 크기</span><br>
<span style="color:#111827">d. sizeof *p = p가 가리키는 타입 한 개의 크기</span><br>
<span style="color:#dc2626">※ malloc(200) 뒤 sizeof p는 200이 아니라 포인터 크기</span><br>
<br>
<span style="color:#1d4ed8">예: 길이를 같이 전달</span><br>
<span style="color:#111827">void send(const uint8_t *data, size_t len);</span><br>
<span style="color:#111827">size_t used = 200U;  send(buf, used);</span><br>
<span style="color:#111827">할당 용량, 실제 유효 길이, 목적지 용량은 서로 다를 수 있음</span><br>
<br>
<span style="color:#1d4ed8">7. 함수 포인터와 callback</span><br>
<span style="color:#111827">a. 함수 이름은 대부분 식에서 함수 시작 주소로 사용됨</span><br>
<span style="color:#111827">b. void (*action)(void): 인자 없고 void 반환인 함수를 가리킴</span><br>
<span style="color:#111827">c. action() 또는 (*action)()으로 간접 호출</span><br>
<span style="color:#111827">d. callback은 호출 시점은 공통으로 두고 동작만 호출자가 넘기는 구조</span><br>
<span style="color:#111827">- event handler, driver abstraction, 정렬 비교 함수에 사용</span><br>
<span style="color:#dc2626">※ 대상 함수와 함수 포인터의 인자·반환 타입이 다르면 cast로 숨기지 말 것</span><br>
<br>
<span style="color:#1d4ed8">예: callback 뼈대</span><br>
<span style="color:#111827">typedef void (*Callback)(void);</span><br>
<span style="color:#111827">void run_when_ready(Callback cb) { cb(); }</span><br>
<span style="color:#111827">→ run_when_ready는 언제 실행할지, caller는 무엇을 할지 결정</span><br>

## 3페이지: 프로그램 메모리와 동적 할당

<span style="color:#1d4ed8">8. C 프로그램 메모리 레이아웃</span><br>
<span style="color:#111827">a. .text: 기계어 코드, 보통 Flash/ROM에 저장</span><br>
<span style="color:#111827">b. .data: 초기값 있는 전역/static, 초기값 이미지는 Flash에도 존재</span><br>
<span style="color:#111827">c. .bss: 초기값 없는 전역/static, 시작 시 0으로 초기화</span><br>
<span style="color:#111827">d. stack: 지역 변수·함수 호출 정보, 호출/반환에 따라 자동 관리</span><br>
<span style="color:#111827">e. heap: malloc으로 얻는 동적 block, free 전까지 유지</span><br>
<span style="color:#dc2626">※ MCU는 RAM이 작으므로 stack·전역·heap 사용량을 함께 예측해야 함</span><br>
<br>
<span style="color:#1d4ed8">그림: 수명으로 구분</span><br>
<span style="color:#111827">함수 호출 → stack frame 생성 → return → 자동 해제</span><br>
<span style="color:#111827">malloc → heap block 생성 → free → 해제</span><br>
<span style="color:#111827">전역/static → 프로그램 시작부터 종료까지 유지</span><br>
<span style="color:#dc2626">※ 포인터가 사라져도 heap block은 자동 해제되지 않음</span><br>
<br>
<span style="color:#1d4ed8">9. malloc 사용 원칙</span><br>
<span style="color:#111827">a. 필요한 크기가 실행 중에 결정될 때 사용</span><br>
<span style="color:#111827">b. 반환값이 NULL인지 확인</span><br>
<span style="color:#111827">c. 소유자와 free 책임을 API 설계에서 명확히 정함</span><br>
<span style="color:#111827">d. free 뒤 포인터를 다시 쓰지 않고, 가능하면 NULL 대입</span><br>
<span style="color:#dc2626">※ leak, double free, use-after-free는 치명적인 메모리 오류</span><br>
<br>
<span style="color:#1d4ed8">10. 실시간 시스템에서의 선택</span><br>
<span style="color:#111827">a. 일반 malloc/free는 실행 시간 변동과 heap fragmentation을 만들 수 있음</span><br>
<span style="color:#111827">b. ISR 안에서는 할당하지 않음</span><br>
<span style="color:#111827">c. 가능하면 정적 버퍼, stack, 고정 블록 pool을 사용</span><br>
<span style="color:#111827">d. 꼭 동적 할당하면 초기화 단계에 한 번 할당하고 실패 경로도 검증</span><br>
<span style="color:#dc2626">※ 실시간성은 평균 속도가 아니라 최악 실행 시간의 예측 가능성</span><br>

## 4페이지: static·extern·모듈화

<span style="color:#1d4ed8">11. static은 위치에 따라 뜻이 다름</span><br>
<span style="color:#111827">a. 함수 지역 static: 이름은 함수 안, 객체 수명은 프로그램 전체</span><br>
<span style="color:#111827">b. 파일 범위 static 변수/함수: 이 .c 파일에서만 보이는 internal linkage</span><br>
<span style="color:#111827">c. 모듈 내부 state와 helper 함수는 static으로 숨기고 API만 공개</span><br>
<span style="color:#dc2626">※ 지역 static은 숨은 공유 상태라 ISR/스레드 재진입 안전성을 따로 검토</span><br>
<br>
<span style="color:#1d4ed8">12. 선언과 정의</span><br>
<span style="color:#111827">a. 선언: 이름·타입을 알림, extern int ticks;</span><br>
<span style="color:#111827">b. 정의: 실제 저장 공간/함수 본문 하나를 만듦, int ticks = 0;</span><br>
<span style="color:#111827">c. 초기화된 extern은 선언이 아니라 정의</span><br>
<span style="color:#111827">d. 공유 전역은 header에 extern 선언, 한 .c에만 정의</span><br>
<span style="color:#dc2626">※ header에 전역 변수 정의를 넣으면 multiple definition 위험</span><br>
<br>
<span style="color:#1d4ed8">13. .h / .c / linker</span><br>
<span style="color:#111827">a. 각 .c와 include 결과는 translation unit</span><br>
<span style="color:#111827">b. compiler: .c → .o, linker: 여러 .o와 library를 연결</span><br>
<span style="color:#111827">c. .h에는 공개 선언·타입·매크로, .c에는 실제 구현</span><br>
<span style="color:#111827">d. include guard로 같은 header의 중복 포함을 방지</span><br>
<span style="color:#111827">- #include는 텍스트 삽입, link는 object file 결합</span><br>
<span style="color:#dc2626">※ undefined reference는 구현 object/library가 link에 빠졌는지 먼저 확인</span><br>
<br>
<span style="color:#1d4ed8">Q. 꼬리질문</span><br>
<span style="color:#111827">- 배열과 포인터가 다른 이유는?</span><br>
<span style="color:#111827">- sizeof p와 sizeof *p의 차이는?</span><br>
<span style="color:#111827">- ISR에서 malloc을 피하는 이유는?</span><br>
<span style="color:#111827">- static 지역 변수는 왜 재진입에 주의해야 하나?</span><br>
<span style="color:#111827">- #include만 했는데 undefined reference가 나는 이유는?</span><br>

## 면접 30초 답변

<span style="color:#1d4ed8">포인터·메모리·모듈화 설명</span><br>
<span style="color:#111827">C에서 포인터는 메모리 주소를 타입과 함께 다루는 변수로, 배열 순회나 함수에서 원본 데이터 접근, 그리고 MCU 레지스터 접근의 기반이 됩니다.</span><br>
<span style="color:#111827">배열은 포인터로 변환될 수 있지만 자체 크기를 가진 객체이므로, 버퍼 API에는 포인터와 길이를 함께 전달해야 합니다. 특히 sizeof 포인터는 동적 메모리 크기가 아니라 주소 크기입니다.</span><br>
<span style="color:#111827">임베디드에서는 stack과 정적 메모리를 우선하고, 동적 할당은 시간 변동과 단편화를 고려해 제한합니다.</span><br>
<span style="color:#dc2626">모듈은 header의 선언과 .c의 단일 정의로 나누고, 내부 상태는 static으로 숨기는 방식이 안전합니다.</span><br>

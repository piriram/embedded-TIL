## 1페이지: 임베디드 시스템의 기본 구조

<span style="color:#1d4ed8">주제: 임베디드 기초</span><br>
<span style="color:#1d4ed8">1. 임베디드 시스템</span><br>
<span style="color:#111827">a. 특정 목적을 위해 기계나 제품 안에 들어간 컴퓨터 시스템</span><br>
<span style="color:#111827">b. PC처럼 범용으로 쓰기보다 정해진 기능을 안정적으로 수행</span><br>
<span style="color:#111827">c. 하드웨어와 소프트웨어가 강하게 묶여 있음</span><br>
<span style="color:#111827">- 예: 세탁기 제어, 자동차 ECU, 의료기기, 로봇, 센서 장비</span><br>
<span style="color:#dc2626">※ 일반 앱보다 하드웨어 상태와 제약을 더 많이 봄</span><br>
<br>
<span style="color:#1d4ed8">그림: 임베디드 기본 흐름</span><br>
<span style="color:#111827">센서 입력 → MCU 판단 → 액추에이터 출력</span><br>
<span style="color:#111827">버튼/센서 → 코드 실행 → LED/모터/부저</span><br>
<span style="color:#dc2626">※ 입력-처리-출력 흐름으로 이해</span><br>
<img src="./assets/filginote_02/embedded_basic_flow.svg" width="720" alt="임베디드 시스템 기본 흐름"><br>


<span style="color:#1d4ed8">2. MCU(Microcontroller Unit)</span><br>
<span style="color:#111827">a. CPU, 메모리, 주변장치가 한 칩 안에 들어간 작은 컴퓨터</span><br>
<span style="color:#111827">b. GPIO, UART, Timer, I2C, SPI, CAN 같은 기능을 내장</span><br>
<span style="color:#111827">cf) peripheral = MCU 안의 주변장치 기능</span><br>
<span style="color:#111827">- STM32F103, ATmega, ESP32 등이 예시</span><br>
<span style="color:#dc2626">※ MCU는 하드웨어 제어에 특화된 작은 컴퓨터</span><br>
<br>
<span style="color:#1d4ed8">그림: MCU 안쪽</span><br>
<span style="color:#111827">+----------------------+</span><br>
<span style="color:#111827">| CPU                  |</span><br>
<span style="color:#111827">| Flash / SRAM         |</span><br>
<span style="color:#111827">| GPIO UART Timer I2C  |</span><br>
<span style="color:#111827">| SPI CAN ADC PWM      |</span><br>
<span style="color:#111827">+----------------------+</span><br>
<span style="color:#dc2626">※ CPU만 있는 게 아니라 주변장치도 같이 있음</span><br>
<br>
<span style="color:#1d4ed8">이미지: MCU 구조</span><br>
<img src="./assets/filginote_02/mcu_structure.svg" width="720" alt="MCU 구조"><br>
<span style="color:#dc2626">※ CPU, memory, peripherals가 한 칩에 있다는 점 확인</span><br>


<span style="color:#1d4ed8">3. CPU / MCU / SoC</span><br>
<span style="color:#111827">a. CPU: 명령어를 실행하는 계산 중심 장치</span><br>
<span style="color:#111827">b. MCU: CPU + 메모리 + 주변장치가 한 칩에 있는 제어용 칩</span><br>
<span style="color:#111827">c. SoC: 더 큰 시스템을 한 칩에 통합한 구조</span><br>
<span style="color:#111827">- SoC는 GPU, Wi-Fi, 가속기 같은 복잡한 기능도 포함 가능</span><br>
<span style="color:#111827">cf) Raspberry Pi 같은 보드는 SoC 기반에 가까움</span><br>
<span style="color:#dc2626">※ 면접에서는 MCU와 CPU를 같은 말처럼 쓰지 않기</span><br>
<br>
<span style="color:#1d4ed8">한 문장</span><br>
<span style="color:#111827">MCU는 센서 입력과 장치 출력을 직접 다루는 제어용 작은 컴퓨터다.</span><br>


## 2페이지: 입력과 출력 제어 구조

<span style="color:#1d4ed8">4. 펌웨어</span><br>
<span style="color:#111827">a. 하드웨어 가까이에서 동작을 제어하는 소프트웨어</span><br>
<span style="color:#111827">b. MCU Flash에 올라가 전원이 켜질 때 실행됨</span><br>
<span style="color:#111827">c. 핀, 레지스터, 통신, 타이머 등을 제어</span><br>
<span style="color:#111827">- 예: 버튼을 읽고 LED를 켜는 코드</span><br>
<span style="color:#111827">- 예: 센서값을 읽어 모터를 제어하는 코드</span><br>
<span style="color:#dc2626">※ 펌웨어는 하드웨어 동작을 책임지는 코드</span><br>
<br>
<span style="color:#1d4ed8">그림: 펌웨어 위치</span><br>
<span style="color:#111827">하드웨어  ←  펌웨어  ←  응용 로직</span><br>
<span style="color:#111827">GPIO/I2C      드라이버      제품 기능</span><br>
<span style="color:#dc2626">※ 펌웨어는 하드웨어와 기능 사이에 있음</span><br>
<img src="./assets/filginote_02/firmware_layers.svg" width="720" alt="펌웨어 위치"><br>


<span style="color:#1d4ed8">5. 센서</span><br>
<span style="color:#111827">a. 외부 상태를 전기 신호나 데이터로 바꾸는 입력 장치</span><br>
<span style="color:#111827">b. 온도, 빛, 움직임, 거리, 압력 등을 측정</span><br>
<span style="color:#111827">- 예: 온도 센서, 조도 센서, MPU6050 IMU</span><br>
<span style="color:#111827">cf) IMU = 가속도/자이로 등 움직임을 측정하는 센서</span><br>
<span style="color:#dc2626">※ 센서는 MCU가 세상을 읽는 입구</span><br>
<br>
<span style="color:#1d4ed8">6. 액추에이터</span><br>
<span style="color:#111827">a. 전기 신호를 실제 동작으로 바꾸는 출력 장치</span><br>
<span style="color:#111827">b. 빛, 소리, 움직임, 열 같은 결과를 만듦</span><br>
<span style="color:#111827">- 예: LED, 모터, 부저, 릴레이</span><br>
<span style="color:#111827">cf) 부저 = 전기 신호를 소리로 바꾸는 부품</span><br>
<span style="color:#dc2626">※ 액추에이터는 MCU가 세상에 영향을 주는 출구</span><br>


<span style="color:#1d4ed8">그림: 센서와 액추에이터</span><br>
<span style="color:#111827">[센서] --입력--> [MCU] --출력--> [액추에이터]</span><br>
<span style="color:#111827">온도              판단 코드          팬/모터</span><br>
<span style="color:#111827">버튼              조건 확인          LED/부저</span><br>
<span style="color:#dc2626">※ 입력과 출력이 동시에 있어야 제어가 됨</span><br>
<img src="./assets/filginote_02/sensor_actuator_flow.svg" width="720" alt="센서와 액추에이터 흐름"><br>
<br>
<span style="color:#dc2626">※ 센서=입력, 액추에이터=출력 관계 확인</span><br>


## 3페이지: 임베디드 실행 방식

<span style="color:#1d4ed8">7. Bare-metal</span><br>
<span style="color:#111827">a. 운영체제 없이 MCU 위에서 코드가 직접 도는 방식</span><br>
<span style="color:#111827">b. main loop와 interrupt 중심으로 동작</span><br>
<span style="color:#111827">c. 구조가 단순하고 자원 사용이 작음</span><br>
<span style="color:#111827">- 예: while(1)에서 버튼 읽고 LED 제어</span><br>
<span style="color:#dc2626">※ 처음 임베디드를 배울 때 동작 원리 이해에 좋음</span><br>
<br>
<span style="color:#1d4ed8">그림: Bare-metal</span><br>
<span style="color:#111827">main loop</span><br>
<span style="color:#111827">↓</span><br>
<span style="color:#111827">GPIO / UART / Timer</span><br>
<span style="color:#111827">↓</span><br>
<span style="color:#111827">Hardware</span><br>


<span style="color:#1d4ed8">8. RTOS(Real-Time Operating System)</span><br>
<span style="color:#111827">a. 여러 task를 정해진 규칙으로 스케줄링</span><br>
<span style="color:#111827">b. queue, semaphore, mutex 같은 동기화 도구 제공</span><br>
<span style="color:#111827">cf) task = RTOS에서 나눠 실행하는 작업 단위</span><br>
<span style="color:#111827">- 예: 센서 task, 통신 task, 제어 task 분리</span><br>
<span style="color:#dc2626">※ 지금은 이름과 역할만 알기</span><br>
<br>
<span style="color:#1d4ed8">9. Embedded Linux</span><br>
<span style="color:#111827">a. 임베디드 장치에서 쓰는 Linux 기반 운영체제</span><br>
<span style="color:#111827">b. 네트워크, 파일시스템, 프로세스, 드라이버 구조가 큼</span><br>
<span style="color:#111827">c. MCU보다 자원이 큰 보드에서 많이 사용</span><br>
<span style="color:#111827">- 예: 라즈베리파이, 산업용 게이트웨이, HMI 장비</span><br>
<span style="color:#111827">cf) HMI = Human-Machine Interface, 사람이 기계 상태를 보고 조작하는 화면/패널</span><br>
<span style="color:#111827">- 예: 공장 설비 터치패널, 로봇 상태 표시 화면, 장비 설정 UI</span><br>
<span style="color:#111827">cf) 같은 층이 아님 = MCU 펌웨어는 하드웨어를 직접 제어하는 코드이고, Embedded Linux는 OS 위에서 앱/드라이버/프로세스가 도는 구조</span><br>
<span style="color:#111827">- MCU 펌웨어: 코드 → 레지스터/핀 직접 제어</span><br>
<span style="color:#111827">- Embedded Linux: 앱 → Linux kernel/driver → 하드웨어 제어</span><br>
<span style="color:#dc2626">※ MCU 펌웨어와 같은 층이 아님</span><br>


<span style="color:#1d4ed8">비교: Bare-metal vs RTOS vs Embedded Linux</span><br>
<span style="color:#111827">Bare-metal: 단순, 직접 제어, 작은 MCU</span><br>
<span style="color:#111827">RTOS: 여러 작업, 실시간성, 중간 복잡도</span><br>
<span style="color:#111827">Embedded Linux: 풍부한 기능, 큰 자원, 복잡한 시스템</span><br>
<span style="color:#111827">cf) Bare-metal부터 잡기 = OS 도움 없이 MCU가 핀/레지스터/인터럽트를 직접 제어하는 흐름부터 이해하기</span><br>
<span style="color:#111827">- 이 기본 흐름을 알아야 RTOS나 Linux가 무엇을 대신 관리해주는지 보임</span><br>
<span style="color:#dc2626">※ 지금은 Bare-metal부터 잡기</span><br>

## 4페이지: 하드웨어 문서 읽기

<span style="color:#1d4ed8">10. 데이터시트</span><br>
<span style="color:#111827">a. 특정 칩의 전기적/물리적 특성을 보는 문서</span><br>
<span style="color:#111827">b. 핀 배치, 전압, 전류, 클럭, 패키지 정보가 있음</span><br>
<span style="color:#111827">c. 회로 연결이나 부품 선택 때 많이 봄</span><br>
<span style="color:#111827">- 예: 이 핀이 5V tolerant인지 확인</span><br>
<span style="color:#dc2626">※ 핀과 전기 조건 확인용</span><br>
<br>
<span style="color:#1d4ed8">11. 레퍼런스 매뉴얼</span><br>
<span style="color:#111827">a. MCU 내부 주변장치 동작 방식을 설명하는 문서</span><br>
<span style="color:#111827">b. 레지스터, 비트, 동작 순서, 상태 플래그가 나옴</span><br>
<span style="color:#111827">c. 펌웨어에서 주변장치를 제어할 때 봄</span><br>
<span style="color:#111827">- 예: UART BRR, I2C SR1/SR2, GPIO ODR/BSRR</span><br>
<span style="color:#dc2626">※ 코드 작성과 디버깅 때 필요</span><br>


<span style="color:#1d4ed8">비교: Datasheet vs Reference Manual</span><br>
<span style="color:#111827">Datasheet: 이 칩의 핀/전기/성능 조건</span><br>
<span style="color:#111827">Reference Manual: 내부 기능을 어떻게 제어하는지</span><br>
<span style="color:#111827">cf) Datasheet는 하드웨어 관점, RM은 펌웨어 관점</span><br>
<span style="color:#dc2626">※ 둘 중 하나만 보면 부족함</span><br>
<br>

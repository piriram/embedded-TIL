# SRAM

> 파생 학습노트: `10_학습자료/cs/임베디드수업/8_MCU_메모리맵과_MMIO.md`
> 최종 갱신: 2026-05-20

---

## 30초 통합 답변

> 면접 직전 이것만 소리내어 읽는다. 입에 붙을 때까지.

SRAM은 MCU가 프로그램 실행 중 변수, 스택, 임시 데이터 등을 저장하는 실제 메모리 영역입니다. STM32 같은 32비트 MCU의 메모리 맵에서는 Flash, System Memory, SRAM, Peripheral Register 영역이 주소 공간 안에 나뉘어 배치되며, 이 노트에서는 SRAM이 `0x20000000`부터 시작하는 영역으로 설명됩니다. CPU가 SRAM 주소에 값을 쓰면 그 값은 실제 메모리에 저장되고, 나중에 같은 주소에서 읽으면 이전에 저장한 값을 다시 가져옵니다. 이 점에서 GPIO나 USART 같은 Peripheral Register 주소와 다릅니다. Peripheral Register는 주소처럼 보이지만 값을 저장하려는 공간이 아니라 하드웨어 동작을 일으키거나 외부 상태를 읽는 인터페이스입니다.

---

## 한 줄 정의

**SRAM은 프로그램 실행 중 데이터를 읽고 쓰기 위해 사용하는 MCU의 실제 휘발성 메모리 영역이다.**

핵심은 **쓴 값을 나중에 다시 읽기 위한 데이터 저장 공간**이라는 점입니다.

---

## 왜 필요한가

프로그램은 실행 중에 계속 변하는 데이터를 저장할 공간이 필요합니다.

예를 들어 지역 변수, 전역 변수의 실행 중 값, 함수 호출 시 사용하는 스택, 임시 계산 결과 같은 데이터는 Flash에 고정된 코드처럼 다룰 수 없습니다. 이런 실행 중 데이터는 빠르게 읽고 쓸 수 있는 RAM 영역에 있어야 하며, MCU에서는 그 역할을 SRAM이 담당합니다.

노트에서는 메모리 접근의 핵심을 “이전에 저장한 값을 그대로 다시 가져온다”로 설명합니다. 이는 I/O 접근이 “물리적 동작을 일으키거나 외부 상태를 읽는 것”과 구분되는 핵심 차이입니다.

---

## 동작 원리

MCU 메모리 맵에서 SRAM은 특정 주소 범위에 배치됩니다. 이 노트의 예시에서는 SRAM 시작 주소가 `0x20000000`입니다.

CPU가 SRAM 주소로 write 요청을 보내면, MCU 내부의 주소 디코더가 해당 주소가 SRAM 범위임을 판단하고 요청을 SRAM으로 보냅니다.

```text
CPU: 0x20000000에 써라
주소 디코더: 이건 SRAM 범위
결과: SRAM에 값 저장
```

반대로 같은 주소에서 read 요청을 보내면 SRAM에 저장되어 있던 값을 다시 읽습니다. 이 점이 Peripheral Register 접근과 다릅니다. Peripheral 주소에 write하면 값 저장이 아니라 GPIO 출력 변경이나 USART 송신 같은 하드웨어 동작이 일어날 수 있습니다.

---

## 언제 쓰는가 / 언제 피하는가

- **쓰는 경우:** 실행 중 바뀌는 데이터, 변수, 스택, 임시 버퍼, 계산 결과 등을 저장할 때 사용합니다.
- **피하거나 주의할 경우:** 전원이 꺼져도 유지되어야 하는 데이터는 SRAM에만 저장하면 안 됩니다. 또한 SRAM 주소가 아닌 Peripheral Register 주소를 일반 RAM처럼 다루면 의도치 않은 하드웨어 동작이나 Hard Fault가 발생할 수 있습니다. 노트에서는 실제 register가 없는 주소에 접근하면 Hard Fault가 발생할 수 있다고 설명합니다.

---

## 대표 예시

노트의 메모리 맵 예시는 다음처럼 주소 범위를 나눕니다.

| 영역 | 시작 주소 | 의미 |
|------|-----------|------|
| Flash | `0x08000000` | 프로그램 코드 |
| System Memory | `0x1FFFF000` | 제조사가 넣어 둔 built-in software, 예: 부트로더 |
| SRAM | `0x20000000` | 실행 중 변수 등이 들어가는 실제 메모리 |
| Peripheral Registers | `0x40000000` 영역 | MMIO 대상인 주변장치 레지스터 |

SRAM은 이 중 “실행 중 변수 등이 들어가는 실제 메모리”로 설명됩니다.

## 비교 / 대안

| 비교 대상 | 핵심 차이 |
|----------|-----------|
| **SRAM** | 실행 중 데이터를 저장하고 다시 읽는 실제 메모리다. |
| **Flash** | 주로 프로그램 코드가 저장되는 비휘발성 메모리 영역이다. |
| **Peripheral Register** | 주소로 접근하지만 실제 RAM이 아니라 주변장치 제어와 상태 확인을 위한 하드웨어 레지스터다. |
| **System Memory** | MCU 제조사가 넣어 둔 built-in software가 위치할 수 있는 영역이다. |

## 꼬리질문 예상

- **Q:** SRAM은 무엇을 저장하나요?
  **A:** 프로그램 실행 중 변수, 스택, 임시 데이터 같은 변경 가능한 데이터를 저장합니다. 노트에서는 SRAM을 “실행 중 변수 등이 들어가는 실제 메모리”라고 설명합니다.

- **Q:** SRAM 주소에 값을 쓰면 어떤 일이 일어나나요?
  **A:** 주소 디코더가 그 주소를 SRAM 범위로 판단하고, 값이 실제 SRAM에 저장됩니다. 나중에 같은 주소를 읽으면 저장한 값을 다시 가져올 수 있습니다.

- **Q:** SRAM과 Peripheral Register의 가장 큰 차이는 무엇인가요?
  **A:** SRAM은 값을 저장했다가 다시 읽는 실제 메모리이고, Peripheral Register는 하드웨어 제어 또는 상태 확인을 위한 주소화된 인터페이스입니다.

- **Q:** SRAM 시작 주소는 항상 `0x20000000`인가요?
  **A:** 이 노트의 STM32 예시에서는 SRAM 시작 주소가 `0x20000000`으로 설명됩니다. 다만 실제 주소 배치는 MCU마다 다르므로 데이터시트나 레퍼런스 매뉴얼을 확인해야 합니다.

- **Q:** CPU는 어떤 주소가 SRAM인지 어떻게 아나요?
  **A:** CPU가 직접 판단하는 것이 아니라, MCU 내부의 주소 디코더가 주소 범위를 보고 SRAM, GPIO, USART 같은 실제 대상으로 연결합니다.

---

## 자주 하는 오해

- **오해:** 주소로 접근하면 전부 SRAM이다.
  - **정확히는:** 주소 공간에는 Flash, SRAM, Peripheral Register 등이 함께 배치됩니다. Peripheral 주소는 RAM이 아니라 하드웨어 레지스터에 연결될 수 있습니다.

- **오해:** SRAM과 Flash는 같은 메모리다.
  - **정확히는:** 이 노트에서 Flash는 프로그램 코드 영역, SRAM은 실행 중 변수 등이 들어가는 실제 메모리 영역으로 구분됩니다.

- **오해:** Peripheral Register도 값을 저장하니 SRAM과 같다.
  - **정확히는:** Peripheral Register는 일반 데이터 저장 공간이 아니라 GPIO, USART 같은 하드웨어를 제어하거나 상태를 읽기 위한 레지스터입니다.

# Memory Mapped I/O, MMIO

## 30초 통합 답변

Memory Mapped I/O는 주변장치 레지스터를 일반 메모리 주소처럼 주소 공간에 배치해서, CPU가 별도 I/O 명령어 없이 일반 `load/store` 명령으로 하드웨어를 제어하는 방식입니다. 예를 들어 어떤 주소는 SRAM에 연결되고, 어떤 주소는 GPIO나 USART 레지스터에 연결되며, CPU가 그 주소에 read/write를 하면 MCU 내부의 주소 디코더가 해당 요청을 실제 메모리나 주변장치로 보냅니다. 이 방식 덕분에 C 포인터나 구조체로 레지스터를 다룰 수 있어 소프트웨어 구조가 단순해지지만, 해당 주소에 RAM이 있는 것은 아니므로 실제 레지스터가 없는 주소를 건드리면 Hard Fault가 발생할 수 있습니다.

---

## 한 줄 정의

**Memory Mapped I/O는 주변장치 레지스터를 일반 메모리 주소처럼 매핑해서, 메모리 접근 명령으로 I/O를 제어하는 방식이다.**

핵심은 **메모리와 I/O를 같은 주소 공간 안에서 다룬다**는 점이다.

## 왜 필요한가

메모리와 I/O를 같은 방식으로 다루면, CPU가 별도의 I/O 전용 명령어를 쓰지 않고도 주변장치를 제어할 수 있다.

즉, GPIO나 USART 같은 장치도 일반 변수처럼 특정 주소에 값을 읽고 쓰는 방식으로 접근할 수 있다. 이 방식은 메모리와 I/O 세계를 통일해 소프트웨어 설계를 단순하게 만드는 추상화다.

## 동작 원리

CPU는 주소와 read/write 요청만 내보낸다. 그 주소가 SRAM인지, GPIO인지, USART인지는 CPU가 직접 판단하는 것이 아니라, MCU 내부의 **버스**와 **주소 디코더**가 주소 범위를 보고 실제 대상으로 연결한다.

예를 들어 `0x20000000`에 쓰면 SRAM에 값이 저장될 수 있고, `0x40020014`에 쓰면 GPIO 출력 레지스터에 값이 전달되어 핀 상태가 바뀔 수 있다. 중요한 점은 `0x40020014`에 RAM 셀이 있는 것이 아니라, 그 주소가 GPIO 하드웨어 내부 레지스터에 연결되어 있다는 것이다.

## 언제 쓰는가 / 언제 피하는가

- **쓰는 경우:** MCU에서 GPIO, USART, SPI, Timer, ADC 같은 주변장치 레지스터를 제어할 때 사용한다.
- **주의할 경우:** 데이터시트나 레퍼런스 매뉴얼에 정의되지 않은 주소, 또는 실제 레지스터가 없는 주소에는 접근하면 안 된다. 그런 주소에 접근하면 유효한 값을 얻지 못할 뿐 아니라 Hard Fault가 발생할 수 있다.

## 대표 예시

```c
#define GPIOA_BASE  0x40020000U
#define USART2_BASE 0x40004400U
```

이 코드는 개발자가 주소를 새로 정하는 것이 아니다. 제조사가 데이터시트나 레퍼런스 매뉴얼에 정의해 둔 GPIOA, USART2의 시작 주소에 코드상 이름을 붙이는 것이다. MCU 내부 회로는 특정 주소 범위로 온 요청을 특정 장치로 보내도록 고정되어 있다.

## 비교 / 대안

| 비교 대상 | 핵심 차이 |
|----------|-----------|
| **Separate I/O Address Space** | 메모리 주소 공간과 I/O 주소 공간을 분리한다. I/O 접근에는 `IN`, `OUT` 같은 전용 명령어가 필요하다. |
| **MMIO** | 메모리와 I/O를 같은 주소 공간에 배치한다. 일반 `load/store` 명령으로 주변장치에 접근한다. |

Separate I/O Address Space를 지원하는 시스템에서도 MMIO를 함께 쓸 수 있으므로, 둘은 반드시 양자택일 관계가 아니다.

## 꼬리질문 예상

- **Q:** MMIO 주소에 값을 쓰면 그 값이 RAM에 저장되나요?
  **A:** 아니다. Peripheral 영역의 주소는 RAM 셀이 아니라 하드웨어 레지스터에 연결되어 있다. 값을 쓰면 저장이 아니라 핀 출력 변경, UART 송신 같은 하드웨어 동작이 일어날 수 있다.

- **Q:** CPU는 이 주소가 GPIO인지 USART인지 어떻게 아나요?
  **A:** CPU가 직접 아는 것이 아니다. CPU는 주소와 read/write 요청만 내보내고, MCU 내부의 주소 디코더와 버스가 주소 범위를 보고 적절한 장치로 연결한다.

- **Q:** MMIO를 쓰면 왜 C 구조체로 레지스터를 다룰 수 있나요?
  **A:** Peripheral 내부 레지스터들이 Base Address에서 일정한 Offset만큼 떨어져 배치되기 때문이다. 특히 32비트 레지스터는 보통 4바이트 단위로 배치되므로 C 구조체 필드 배치와 잘 맞는다.

- **Q:** 잘못된 MMIO 주소를 읽으면 그냥 0이 나오나요?
  **A:** 그렇게 단정하면 안 된다. 실제 register가 없는 unassigned address에 접근하면 유효한 값을 얻지 못할 뿐 아니라 Hard Fault Interrupt가 발생해 시스템이 멈출 수 있다.

## 자주 하는 오해

- **오해:** MMIO 주소에는 실제 RAM이 있다.
  - **정확히는:** Peripheral 주소는 RAM이 아니라 GPIO, USART 같은 하드웨어 레지스터에 연결된 주소다.

- **오해:** 개발자가 코드에서 I/O 주소를 마음대로 정한다.
  - **정확히는:** 주소는 MCU 제조사가 하드웨어 설계로 고정해 둔다. 개발자는 데이터시트나 레퍼런스 매뉴얼의 주소표를 보고 코드에서 이름을 붙여 사용하는 것이다.

- **오해:** Separate I/O 방식과 MMIO는 반드시 둘 중 하나만 가능하다.
  - **정확히는:** Separate I/O Address Space를 지원하는 시스템에서도 MMIO를 함께 사용할 수 있다.

## 자주 놓치는 정확 표현

| 모호한 말 | 정확한 용어 |
|----------|-------------|
| 메모리처럼 보이는 장치 | Memory Mapped I/O |
| 장치 주소 | Peripheral Register Address |
| 시작 주소 | Base Address |
| 떨어진 위치 | Offset |
| 주소 보고 장치 고르는 회로 | Address Decoder |
| I/O 전용 주소 공간 | Separate I/O Address Space |
| 없는 주소 | Unassigned Address |
| 시스템 뻗음 | Hard Fault |

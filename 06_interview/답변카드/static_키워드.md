# `static` 키워드

> 출처: 자체 작성
> 최종 갱신: 2026-05-30

---

## 30초 통합 답변

> 면접 직전 이것만 소리내어 읽는다.

`static`은 **저장 기간(storage duration)과 연결(linkage) 두 가지를 동시에 제어하는 C 키워드**입니다. 함수 안에서 지역 변수에 붙이면 그 변수는 함수 호출이 끝나도 사라지지 않고 프로그램 종료까지 살아남으며, 다음 호출 때 이전 값을 그대로 유지합니다. 파일 범위에서 전역 변수나 함수에 붙이면 외부 연결을 끊어 다른 파일에서 이름으로 접근하지 못하게 만듭니다. 즉 같은 키워드가 **수명을 늘리는 용도**와 **가시성을 좁히는 용도** 두 방향으로 쓰입니다. 임베디드에서는 인터럽트 핸들러가 호출 사이에 상태를 유지해야 할 때 함수 안 `static` 변수가 자주 쓰이고, 모듈 내부 헬퍼 함수는 파일 외부에 노출되지 않도록 `static`으로 막아 심볼 충돌과 의도하지 않은 호출을 차단합니다.

---

## 한 줄 정의

`static`은 **저장 기간을 정적(static storage duration)으로 만들고, 파일 범위에서는 외부 연결(external linkage)을 내부 연결(internal linkage)로 바꾸는 한정자**다.

핵심은 **"수명 연장"과 "가시성 제한"이 같은 키워드에 동시에 들어 있다는 점**.

## 왜 필요한가

C는 변수의 수명과 가시성을 분리해서 제어할 수단이 부족하다. `static`은 두 축을 동시에 다룬다.

수명 측면:
- 함수 지역 변수는 기본적으로 스택에 잡혀 호출이 끝나면 사라진다.
- 함수 호출 간에 값을 유지해야 할 때 전역으로 빼면 다른 함수도 건드릴 수 있어 캡슐화가 깨진다.
- `static` 지역 변수는 **프로그램 시작 시 한 번 0(또는 명시값)으로 초기화되고 종료까지 유지된다**. 하지만 이름은 함수 안에서만 보인다.

가시성 측면:
- 전역 변수와 함수는 기본적으로 외부 연결을 가진다. 다른 `.c` 파일에서 `extern` 선언만 하면 접근할 수 있다.
- 라이브러리 내부 헬퍼 함수가 외부로 노출되면 다른 모듈이 우연히 같은 이름을 정의했을 때 링커 충돌이 난다.
- 파일 범위 `static`은 해당 심볼을 그 파일 안에만 묶어 외부 노출을 막는다.

## 동작 원리

### 함수 안 지역 변수

```c
void counter(void) {
    static unsigned int n = 0;
    n++;
    printf("%u\n", n);
}
```

- `n`은 BSS 또는 data 영역에 잡힌다(스택 아님).
- 첫 호출 직전에 0으로 초기화된다(런타임 초기화 아님 — 프로그램 로드 시점).
- 호출이 끝나도 사라지지 않는다. 다음 호출 때 이전 값이 유지된다.
- 함수 밖에서는 이름으로 접근할 수 없다.

### 파일 범위 변수 / 함수

```c
// motor.c
static int internal_step = 0;          // motor.c 안에서만 보임
static void update_pwm(int duty) { }   // motor.c 안에서만 호출 가능

void motor_set_speed(int rpm) {        // 외부 노출 (extern linkage)
    update_pwm(rpm * 2);
    internal_step++;
}
```

- `internal_step`, `update_pwm`은 `motor.c` 안에서만 보인다.
- 다른 파일에서 `extern int internal_step;` 해도 링크 실패한다.
- 같은 이름의 `static` 심볼이 여러 파일에 있어도 충돌하지 않는다(각자 별개).

### 초기화 시점

```c
static int x = 5;        // 프로그램 로드 시 5로 초기화 (한 번)
static int y;            // BSS에 잡혀 0으로 초기화
```

런타임에 매번 초기화되는 게 아니다. 함수 안 `static` 변수도 마찬가지로 **첫 진입 시점이 아닌 프로그램 시작 시점**에 초기화된다.

## 임베디드에서 자주 쓰는 패턴

### 1. 인터럽트 핸들러가 호출 사이 상태 유지

```c
void EXTI0_IRQHandler(void) {
    static uint32_t last_tick = 0;
    uint32_t now = HAL_GetTick();
    if (now - last_tick < 50) return;  // 50ms debounce
    last_tick = now;
    // process button
}
```

전역 변수로 빼도 되지만 다른 코드가 건드릴 위험을 차단한다.

### 2. 모듈 내부 상태 캡슐화

```c
// i2c_driver.c
static I2C_HandleTypeDef *hi2c_internal;

void i2c_driver_init(I2C_HandleTypeDef *h) {
    hi2c_internal = h;
}
```

`hi2c_internal`은 다른 파일이 직접 못 만진다. `i2c_driver_init`을 거쳐야만 한다.

### 3. 모듈 내부 헬퍼 함수 숨김

```c
// uart.c
static void wait_tx_empty(void) { while (!(USART1->SR & USART_SR_TXE)); }

void uart_send_byte(uint8_t b) {
    wait_tx_empty();
    USART1->DR = b;
}
```

`wait_tx_empty`는 외부에서 호출되면 안 된다. `static`으로 막는다.

## 자주 놓치는 점

- 함수 안 `static` 변수는 **재진입(reentrancy)에 안전하지 않다**. 인터럽트가 같은 함수를 다시 부르면 상태가 깨진다.
- `static` 지역 변수는 멀티스레드에 안전하지 않다(스레드 간 공유됨).
- 초기화는 한 번이지만 **명시 초기화 값은 ROM/Flash에서 RAM으로 복사**된다(startup 코드가 처리).
- `static const`는 보통 ROM/Flash에 배치된다(컴파일러/링커 스크립트에 따라 다름).

## 비교 / 대안

| 비교 대상 | 핵심 차이 |
|----------|-----------|
| 일반 지역 변수 | 호출마다 스택에 새로 잡힘. 호출 끝나면 사라짐. |
| 일반 전역 변수 | 프로그램 종료까지 살아남지만 모든 파일에서 보임(외부 연결). |
| `static` 지역 변수 | 프로그램 종료까지 살아남되 이름은 함수 안에서만 보임. |
| `static` 파일 범위 변수/함수 | 프로그램 종료까지 살아남되 이름은 그 파일 안에서만 보임(내부 연결). |
| `extern` | 다른 파일에 있는 외부 연결 심볼을 가져온다. `static`과 반대 방향. |
| `const` | 값을 수정 못 함을 표시. 수명·가시성과는 별개 축. |

## 꼬리질문 예상

- **Q:** `static`을 함수 안 지역 변수에 붙이면 어떻게 되나요?
  **A:** 저장 기간이 정적이 되어 함수 호출이 끝나도 값이 유지된다. 이름은 여전히 그 함수 안에서만 보인다.

- **Q:** 파일 범위 `static`은 무엇을 의미하나요?
  **A:** 해당 변수나 함수의 연결을 외부 연결에서 내부 연결로 바꿔, 다른 파일에서 이름으로 접근하지 못하게 한다.

- **Q:** `static` 지역 변수의 초기화 시점은 언제인가요?
  **A:** 첫 함수 호출 시점이 아니라 프로그램 로드 시점에 한 번 초기화된다.

- **Q:** 인터럽트 핸들러에 `static` 지역 변수를 쓰면 안전한가요?
  **A:** 그 인터럽트가 자기 자신에 의해 재진입되지 않는다는 가정하에만 안전하다. 중첩 인터럽트 환경에서는 위험할 수 있다.

- **Q:** `static`과 `const`를 같이 쓰면 어디에 배치되나요?
  **A:** 보통 ROM/Flash에 배치된다. 정확한 배치는 컴파일러와 링커 스크립트에 따라 다르다.

## 자주 하는 오해

- **오해:** `static`은 한 가지 의미만 가진다.
  - **정확히는:** 위치에 따라 수명 연장(함수 안 지역 변수)과 가시성 제한(파일 범위) 두 의미를 가진다.

- **오해:** `static` 변수는 함수가 처음 호출될 때 초기화된다.
  - **정확히는:** 프로그램 시작 시점에 한 번 초기화된다.

- **오해:** `static` 변수는 스레드 안전하다.
  - **정확히는:** 모든 스레드가 같은 인스턴스를 공유한다. 별도 동기화가 필요하다.

- **오해:** `static`을 떼도 동작은 같다.
  - **정확히는:** 떼면 변수는 스택 변수가 되어 호출마다 초기화되고, 파일 범위 함수는 다른 파일에서 호출 가능해진다.

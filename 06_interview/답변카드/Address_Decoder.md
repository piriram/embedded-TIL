# 주소 디코더, Address Decoder

> 파생 학습노트: `10_주제별/cs/임베디드수업/8_MCU_메모리맵과_MMIO.md`
> 최종 갱신: 2026-05-20

---

## 30초 통합 답변

> 면접 직전 이것만 소리내어 읽는다. 입에 붙을 때까지.

주소 디코더는 CPU가 내보낸 주소를 보고 그 read/write 요청을 SRAM, Flash, GPIO, USART 같은 실제 대상 중 어디로 보낼지 결정하는 MCU 내부 하드웨어 회로입니다. CPU는 “이 주소에서 읽어라” 또는 “이 주소에 써라”는 요청만 내보낼 뿐, 그 주소가 RAM인지 주변장치인지 직접 판단하지 않습니다. 예를 들어 `0x20000000` 범위는 SRAM으로, `0x40020000` 범위는 GPIOA로, `0x40004400` 범위는 USART2로 연결되도록 칩 내부 회로가 고정되어 있고, 주소 디코더가 이 범위를 해석해 요청을 알맞은 장치로 보냅니다. 따라서 MMIO에서 주변장치를 메모리처럼 다룰 수 있는 이유는 CPU가 주변장치를 특별히 인식해서가 아니라, 주소 디코더와 버스가 주소 범위를 하드웨어 장치에 연결해 주기 때문입니다.

---

## 한 줄 정의

**주소 디코더는 CPU가 내보낸 주소를 해석해서 해당 접근을 어떤 메모리나 주변장치로 보낼지 결정하는 하드웨어 회로다.**

핵심은 **소프트웨어 함수가 아니라 MCU 내부 하드웨어**라는 점입니다.

---

## 왜 필요한가

CPU 입장에서는 모든 접근이 단순한 주소 기반 read/write 요청입니다.

```text
주소 A에서 값을 읽어라
주소 B에 값을 써라
```

하지만 MCU 안에는 Flash, SRAM, GPIO, USART, Timer 같은 여러 대상이 존재합니다. 따라서 특정 주소 접근이 어느 장치로 가야 하는지 나눠 주는 회로가 필요합니다. 그 역할을 하는 것이 주소 디코더입니다.

---

## 동작 원리

주소 디코더는 CPU가 버스에 내보낸 주소를 보고, 그 주소가 어떤 범위에 속하는지 판단합니다.

```text
CPU: 0x20000000에 써라
주소 디코더: 이건 SRAM 범위
결과: SRAM에 값 저장

CPU: 0x40020000에 써라
주소 디코더: 이건 GPIOA 범위
결과: GPIOA 레지스터에 값 전달

CPU: 0x40004400에 써라
주소 디코더: 이건 USART2 범위
결과: USART2 레지스터에 값 전달
```

즉, 주소 디코더는 주소값을 보고 요청을 분기시키는 하드웨어입니다. C 코드에서 `address_decoder()` 같은 함수를 호출하는 방식이 아닙니다.

---

## 언제 쓰는가 / 언제 피하는가

- **쓰는 경우:** 개발자가 직접 “쓴다”기보다, MCU 내부에서 항상 동작합니다. CPU가 Flash, SRAM, GPIO, USART 같은 주소에 접근할 때 주소 디코더가 자동으로 요청을 연결합니다.
- **주의할 경우:** 데이터시트에 없는 주소나 실제 register가 없는 주소에 접근하면 주소 디코더가 정상적인 대상으로 연결하지 못하거나, 시스템에서 Hard Fault가 발생할 수 있습니다. 노트에서는 unassigned address 접근이 유효한 값을 주지 않을 뿐 아니라 Hard Fault Interrupt를 일으킬 수 있다고 설명합니다.

---

## 대표 예시

노트의 예시에서는 주소 범위가 다음처럼 연결됩니다.

| 주소 범위 | 연결 대상 |
|----------|-----------|
| `0x20000000` ~ `0x2000FFFF` | SRAM |
| `0x40020000` ~ `0x400203FF` | GPIOA |
| `0x40004400` ~ `0x400047FF` | USART2 |

이 연결은 개발자가 실행 중에 정하는 것이 아닙니다. MCU 설계자가 칩 내부 회로로 정해 두고, 개발자는 데이터시트나 레퍼런스 매뉴얼의 주소표를 보고 사용합니다.

## 비교 / 대안

| 비교 대상 | 핵심 차이 |
|----------|-----------|
| **CPU** | 주소와 read/write 요청을 내보낸다. 주소가 어떤 장치인지 직접 판단하지 않는다. |
| **주소 디코더** | 주소 범위를 해석해 요청을 SRAM, GPIO, USART 같은 대상으로 연결한다. |
| **버스** | CPU와 메모리/주변장치 사이에서 주소, 데이터, 제어 신호가 이동하는 통로 역할을 한다. |
| **Peripheral Register** | 주소 디코더가 연결해 주는 실제 하드웨어 레지스터 대상이다. |

## 꼬리질문 예상

- **Q:** CPU는 주소가 GPIO인지 SRAM인지 어떻게 아나요?
  **A:** CPU가 직접 아는 것이 아닙니다. CPU는 주소와 read/write 요청만 내보내고, 주소 디코더와 버스가 주소 범위를 보고 실제 대상으로 연결합니다.

- **Q:** 주소 디코더는 C 코드에서 호출하는 함수인가요?
  **A:** 아닙니다. 주소 디코더는 MCU 내부 하드웨어 회로입니다. CPU가 주소와 read/write 요청을 내보내면 회로가 자동으로 주소 범위를 해석합니다.

- **Q:** 개발자가 GPIO 주소를 코드에서 마음대로 정할 수 있나요?
  **A:** 아닙니다. GPIO나 USART의 주소는 MCU 제조사가 하드웨어 설계로 고정해 둡니다. 개발자는 문서에 나온 주소에 이름을 붙여 사용하는 것입니다.

- **Q:** MMIO에서 주소 디코더가 중요한 이유는 무엇인가요?
  **A:** MMIO는 주변장치를 메모리 주소처럼 접근하는 방식입니다. 이때 특정 주소 접근을 실제 GPIO, USART 같은 주변장치로 연결해 주는 회로가 주소 디코더이므로 핵심 구성 요소입니다.

- **Q:** 잘못된 주소에 접근하면 주소 디코더가 그냥 무시하나요?
  **A:** 그렇게 단정하면 안 됩니다. 노트에 따르면 실제 register가 없는 unassigned address에 접근하면 유효한 값을 얻지 못할 뿐 아니라 Hard Fault가 발생할 수 있습니다.

## 자주 하는 오해

- **오해:** CPU가 GPIO, USART 같은 주변장치를 직접 인식한다.
  - **정확히는:** CPU는 주소 기반 read/write 요청만 내보내고, 주소 디코더가 주소 범위를 해석해 해당 장치로 연결합니다.

- **오해:** 주소 디코더는 펌웨어 코드의 일부다.
  - **정확히는:** 주소 디코더는 MCU 칩 내부의 하드웨어 회로입니다.

- **오해:** `#define GPIOA_BASE 0x40020000U`는 GPIO 주소를 새로 정하는 코드다.
  - **정확히는:** 이미 하드웨어에 정해진 GPIOA 주소에 코드상 이름을 붙이는 것입니다.

- **오해:** 주소 숫자만 맞으면 어떤 장치든 접근 가능하다.
  - **정확히는:** 주소 범위는 하드웨어 설계와 문서에 의해 정해져 있으며, 정의되지 않은 주소 접근은 Hard Fault를 일으킬 수 있습니다.

## 자주 놓치는 정확 표현

| 모호한 말 | 정확한 용어 |
|----------|-------------|
| 주소 보고 고르는 것 | Address Decoder |
| 장치로 보내는 회로 | Address Decoding Logic |
| CPU가 장치를 안다 | Address Decoder가 주소 범위로 연결한다 |
| 주소 연결 | Address Mapping |
| 주소표 | Memory Map |
| 장치 시작 주소 | Base Address |
| 실제 레지스터 없는 주소 | Unassigned Address |
| 시스템이 뻗음 | Hard Fault |

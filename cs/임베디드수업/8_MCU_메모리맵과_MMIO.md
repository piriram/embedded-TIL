# Lesson 8 — MCU Memory Map & Memory Mapped I/O

**주제:** MCU 메모리 맵과 Memory Mapped I/O 개념, 주변장치 레지스터 제어 원리
**원본 강의:** [Lesson 8. The MCU Memory Map and Memory Mapped I/O (YouTube)](https://www.youtube.com/watch?v=bWMsBXNAOAE)

---

## 1. 데이터를 읽고 쓰는 두 가지 시나리오: Memory vs I/O

컴퓨터 내부에서 데이터를 읽고 쓸 때, 우리가 접근하는 대상은 크게 두 가지로 나눌 수 있어.

| 구분 | 주요 목적 | 특징 | 예시 |
| --- | --- | --- | --- |
| **Memory (메모리)** | 데이터 저장 및 로드 | 이전에 저장한 값을 그대로 다시 읽어옴 | Flash에서 프로그램 읽기, RAM에 변수 쓰기 |
| **I/O (입출력)** | 물리적인 동작 수행 | 데이터 저장이 목적이 아님 (읽기/쓰기 전용 존재) | LED 켜기/끄기, 키보드 입력 확인, UART 통신 |

---

## 2. I/O를 제어하는 방식 (Memory Mapped I/O의 탄생)

I/O와 메모리를 어떻게 주소로 지정할 것인가에 대해 두 가지 접근법이 있어. 우리가 집중해야 할 것은 두 번째 방식이야.

| 접근법 | 개념 | 특징 및 예시 |
| --- | --- | --- |
| **방식 1: 독립된 주소 공간** | 메모리 주소와 I/O 주소를 완전히 분리함 | I/O 전용 어셈블리 명령어가 따로 필요함 (Intel 8085, x86 계열) |
| **방식 2: Memory Mapped I/O** | **I/O를 메모리와 동일하게 취급하여 주소를 할당함** | 주소 'X'는 RAM, 주소 'Y'는 LED 제어용으로 사용. 소프트웨어 설계가 매우 직관적임 (STM32 등 대부분의 최신 MCU) |

> **주의**
> Memory Mapped I/O에서 I/O 장치는 실제 메모리(RAM)가 아니야! 타이머, UART 같은 하드웨어지만, 프로그래머가 접근하기 쉽도록 **'메모리 주소'라는 껍데기**를 씌워둔 강력한 추상화(Abstraction) 개념이야.

---

## 3. Peripheral Registers (주변장치 레지스터) 제어 원리

Memory Mapped I/O 환경에서 주변장치(타이머, 통신 모듈 등)를 제어하려면 해당 장치의 레지스터(Register)를 읽고 써야 해.

- **주소 지정 방식:** 주변장치의 시작점인 `Base Address(기본 주소)`에 각 레지스터의 `Offset(오프셋)`을 더해서 특정 레지스터의 주소를 계산해.
- **오프셋 규칙:** STM32는 32비트(4바이트) 시스템이므로, 레지스터 오프셋은 0, 4, 8과 같이 **4의 배수**로 증가해.
- **소프트웨어 모델링:** 이 구조는 C 언어의 배열(Array)이나 구조체(Struct)와 완벽하게 매칭되기 때문에 코딩하기 매우 편리해.

**[예시: USART 제어 레지스터]**

- **USART_SR (Status Register):** 현재 상태 확인 (수신된 데이터가 있는지, 전송할 공간이 있는지, 에러가 발생했는지 등)
- **USART_DR (Data Register):** 데이터 전송 및 수신 (읽으면 수신 데이터 획득, 쓰면 데이터 송신)
- **Base Address:** MCU에는 여러 개의 USART가 있으므로 데이터시트를 통해 USART1, USART2 각각의 Base Address를 확인해야 해.

## 4. STM32 MCU 전체 메모리 맵 (Memory Map)

MCU는 32비트 주소 체계를 사용하므로 총 4GB ($2^{32}$ 바이트)의 주소 공간(0x00000000 ~ 0xFFFFFFFF)을 가져. 주요 영역은 다음과 같아.

| 메모리 영역 | 시작 주소 | 설명 |
| --- | --- | --- |
| **Flash Memory** | `0x0800 0000` | 우리가 작성한 프로그램 코드가 저장되는 곳 |
| **System Memory** | `0x1FFF F000` | 부트로더 등 제조사가 구워놓은 내장 소프트웨어 |
| **SRAM** | `0x2000 0000` | 프로그램 실행 중 변수 등이 저장되는 실제 메모리 |
| **Peripheral Registers** | `0x4000 0000` 영역 | GPIO, Timer, UART 등 주변장치 레지스터가 매핑된 곳 |

## 5. 시험/실무에서 주의할 특수 메모리 및 팁

> **예외**
> 일반 메모리 모델에서 벗어나는 특수 케이스들. 코딩 시 반드시 주의.

- **Reset Vector (리셋 벡터):** 전원이 켜졌을 때 MCU가 가장 처음 실행할 코드의 주소를 담고 있는 포인터야. STM32에서는 주소 `0x0000 0004`에 위치해.
- **Interrupt Vector Table (인터럽트 벡터 테이블):** 리셋 벡터 바로 다음에 위치하며, 각 인터럽트 발생 시 실행할 핸들러(함수)의 주소들이 모여있는 곳이야.
- **하드웨어 주소 할당의 여유:** 특정 주변장치(예: USART)가 28바이트(7개 레지스터)만 사용하더라도 하드웨어 설계의 편의상 1024바이트 같은 큰 블록을 통째로 할당해. 주소 공간이 4GB로 아주 넉넉하기 때문이야.
- **Hard Fault 주의:** 넉넉하게 할당된 공간 중에서 아무것도 연결되지 않은 주소(Unassigned Address)에 접근하면, 유효한 값을 얻지 못할 뿐만 아니라 치명적인 `Hard Fault Interrupt`가 발생해서 시스템이 뻗을 수 있으니 코딩할 때 절대 주의해야 해!
- **주소 알리아싱(Aliasing):** 하드웨어 설계상 Flash 메모리는 `0x0800 0000`뿐만 아니라 주소 `0x0000 0000`에서도 똑같이 접근할 수 있도록 매핑되어 있어. 혼동하지 말 것!

## 면접 답변 (30초 분량)

> `/easy-quiz` 실행 시 이 섹션이 정답 카드로 사용됩니다.

- **한 줄 정의:** Memory Mapped I/O는 **주변장치 레지스터를 일반 메모리 주소처럼 매핑**해서, 메모리 접근 명령(load/store)만으로 I/O를 제어하는 방식이다.
- **왜 필요:** I/O 전용 명령어(in/out)를 따로 익히지 않아도 C 포인터·구조체로 직관적으로 하드웨어를 다룰 수 있어, MCU 소프트웨어 설계가 단순해진다.
- **동작:** STM32 같은 32비트 MCU는 4GB 주소 공간을 Flash(`0x0800 0000`), SRAM(`0x2000 0000`), Peripheral(`0x4000 0000`) 등으로 분할한다. 주변장치는 Base Address + Offset(4의 배수)로 레지스터에 접근하고, 이 구조가 C 구조체와 정확히 매칭된다.
- **비교:** Intel 8085·x86 계열의 독립 I/O 주소 공간 방식과 달리, 전용 명령어 없이 일반 메모리 명령으로 처리한다. 단점은 주소 공간 일부를 I/O가 점유한다는 것.
- **30초 통합 답변:**
  > Memory Mapped I/O는 주변장치 레지스터를 메모리 주소처럼 다루는 방식입니다. STM32 같은 32비트 MCU는 4GB 주소 공간을 Flash, SRAM, Peripheral 영역으로 나누고, 주변장치는 Base Address에 4의 배수 오프셋을 더해 접근합니다. 이 구조가 C 구조체와 매칭되어 포인터 캐스팅만으로 레지스터를 제어할 수 있어, x86처럼 별도 I/O 명령어 없이 직관적인 코딩이 가능합니다. 단, 할당되지 않은 주소를 건드리면 Hard Fault가 발생할 수 있으니 주의해야 합니다.

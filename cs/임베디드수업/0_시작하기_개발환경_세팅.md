# 시작하기 — 임베디드 개발 환경 세팅

**원본 강의:** [#0 Modern Embedded Systems Programming: Getting Started (YouTube)](https://www.youtube.com/watch?v=hnj-7XwTYRI)

이 강의는 "Modern Embedded Systems Programming" 코스의 0강(소개편)이다. 기술 개념 강의가 아니라 코스가 무엇을 다루는지, 따라 하려면 어떤 하드웨어·소프트웨어가 필요하고 어떻게 설치하는지를 설명한다. 이 노트만 읽어도 강의를 따로 볼 필요 없이 개발 환경을 세팅할 수 있도록 정리했다.

---

## 1. 코스의 목표와 접근 방식

이 코스는 임베디드 마이크로컨트롤러를 "모던한 방식"으로, 기초부터 현대 임베디드 프로그래밍 실무까지 다룬다.

이 코스의 차별점은 **자주 머신 레벨(machine level)까지 내려가서** 마이크로컨트롤러 안에서 실제로 무슨 일이 일어나는지를 직접 보여준다는 점이다. 강사가 이렇게 하는 이유는 명확하다 — 이 깊은 이해가 있어야 개념을 더 효율적으로, 더 큰 자신감을 가지고 적용할 수 있기 때문이다. 단순히 "이 함수를 호출하면 LED가 켜진다"가 아니라, 그 호출이 레지스터와 메모리에서 어떻게 동작하는지를 봐야 진짜로 안다는 입장이다.

강사는 Miro Samek으로, 30년 이상 경력의 임베디드 소프트웨어 엔지니어다. 이 영상 코스와 그의 책·기사·컨퍼런스 발표는 많은 개발자가 실력을 키우고, 까다로운 면접을 통과하고, 임베디드 프로그래밍 직무에 취업하는 데 도움을 줬다.

> 이 코스의 핵심 철학: 추상화 계층 위에서만 코딩하지 말고, 머신 레벨로 내려가 MCU 내부 동작을 직접 확인하라.

---

## 2. 이 코스가 아직도 유효한가

이 코스는 2013년부터 이어져 왔다. 그래서 "지금도 여전히 유효한가?"라는 질문을 자주 받는다. 강사의 답은 "그렇다(YES)"이며, 오히려 처음보다 지금이 더 유효하다고 말한다. 이유는 두 가지다.

1. **본질적이고 기초적인 개념에 집중한다.** 임베디드 프로그래밍의 근본 개념은 유행을 타지 않는다. 시간이 지나도 낡지 않는다.
2. **ARM Cortex-M 아키텍처 기반이다.** 이 코스는 널리 쓰이는 ARM Cortex-M 아키텍처를 바탕으로 한다. Cortex-M은 인기가 폭발적으로 늘었고, ARM Cortex-M 지식은 고용주가 가장 원하는 스킬이다.

---

## 3. 전제 조건

- **C 언어 기초.** 코스는 기초부터 시작하지만, 그 기초 부분은 짧고 C의 임베디드 측면에 집중되어 있다. 따라서 일반적인 C 언어 학습을 별도로 보충해야 할 수 있다.
- **CPU 동작 원리.** CPU가 어떻게 동작하는지 알아 두면 좋다.

> **주의**
> 코스가 "기초부터 시작한다"고 해서 C를 전혀 몰라도 된다는 뜻이 아니다. 기초 설명은 짧고 임베디드 관점에 한정되므로, C 문법 자체는 따로 공부해 둬야 한다.

---

## 4. 따라 하려면 필요한 것 — 하드웨어와 소프트웨어

이 코스는 PC에서 프로젝트를 직접 따라 하며 실행하는 것을 권장한다(그래야 제대로 배운다). 따라 하려면 두 가지가 필요하다.

- **하드웨어:** 임베디드 보드
- **소프트웨어:** 임베디드 개발 툴셋

### 메인 보드 — TivaC LaunchPad

코스 전반에 쓰이는 메인 보드는 Texas Instruments의 **TivaC LaunchPad**이며, **ARM Cortex-M4F** CPU 기반이다.

이 보드를 쓰는 이유:

- 저렴하다.
- self-contained(보드 하나로 완결적)이다.
- **내장 하드웨어 디버거**를 포함한다. 이 디버거가 single-step 디버깅과 CPU 내부 상태 검사를 가능하게 하는데, 이건 이 코스에 필수다. 머신 레벨로 내려가서 보려면 CPU 안을 들여다볼 수단이 있어야 하기 때문이다.
- 여전히 생산 중이며 여러 유통사에서 구할 수 있다.

### 추가 보드 — STM32 NUCLEO-C031C6

코스 다운로드에는 이제 더 새로운 **STM32 NUCLEO-C031C6** 보드용 프로젝트 버전도 포함된다. 이 보드는 **ARM Cortex-M0+** CPU 기반이다.

- TivaC와 마찬가지로 저렴하고 self-contained이다.
- 내장 하드웨어 디버거는 TivaC보다 **더 다재다능(versatile)**하다.

앞으로 다른 저렴한 ARM Cortex-M 보드가 추가될 수도 있다.

> 처음 몇 강의는 **시뮬레이터**를 사용하므로 하드웨어가 당장 필요하지 않다. 다만 MCU 주변장치(peripheral)와 상호작용하는 후반 강의에서는 실제 임베디드 보드가 필요하다.

## 5. USB 드라이버 설치 (보드 처음 연결 시)

임베디드 보드를 받아서 USB 포트에 처음 꽂으면, USB 드라이버가 제대로 설치됐는지 확인해야 한다.

확인 절차(Windows 기준):

1. Windows 아이콘을 우클릭하고 **Device Manager**를 연다.
2. **TivaC 보드의 올바른 드라이버는 "Stellaris In-Circuit Debug Interface"**다. 그 외 다른 것이 보이면 드라이버를 재설치해야 한다.

재설치 절차:

1. 올바른 USB 드라이버를 먼저 다운로드한다. 다운로드 위치는 보드 패키징 설명에 적혀 있거나, 이 코스의 companion 웹페이지 `state-machine.com/video-course`에서 받을 수 있다.
2. 다운로드한 드라이버를 디스크 어딘가에 압축 해제한다.
3. Device Manager에서 해당 장치 설명을 우클릭하고 **"Update Driver"**를 선택한다.
4. **"Browse my computer for drivers"**를 선택하고, 압축을 푼 디렉터리를 지정한다.

> **주의**
> USB 설치가 어떤 이유로든 안 되면, 언제든 **"Uninstall device"**를 누른 뒤 다시 "Update driver"를 시도하면 된다.

이 절차는 한 보드당 한 번만 하면 된다. 단, 다른 보드를 새로 받으면 그 보드에 대해 다시 해야 한다. 예를 들어 **NUCLEO 보드는 "ST-Link" 드라이버**를 사용한다.

## 6. 임베디드 개발 툴셋 — IAR와 KEIL

소프트웨어 쪽에서는 임베디드 개발 툴셋이 필요하다. 이 코스는 두 가지 전문 툴셋을 다룬다.

### IAR Embedded Workbench for ARM

코스는 처음에 IAR Embedded Workbench for ARM으로 시작했다. 좋은 컴파일러와 안정적인 디버거를 갖춘 전문 툴셋이다.

- 오랫동안 무료 **size-limited KickStart 라이선스**로 제공됐으나, 최근 이게 바뀌어서 지금은 **2주 평가판 라이선스**가 유일한 무료 옵션으로 보인다.
- 그래서 코스 프로젝트 다운로드가 갱신되어, 이제 KEIL-MDK를 포함한 여러 툴셋용 버전을 담고 있다.
- **영상 1~18강은 IAR로 진행**되므로, 영상과 동일한 툴셋을 쓰고 싶으면 IAR 평가판을 받으면 된다. 설치는 간단하지만 시간이 좀 걸린다.

설치 팁:

- **공백과 특수문자가 없는 디렉터리명**에 설치할 것을 권장한다. 예: `C:\tools\IAR`.
- 처음 실행하면 라이선스를 요청해야 할 수 있다. IAR에 등록하면 이메일로 라이선스 키를 받고, 그 키를 라이선스 다이얼로그에 입력한다.

### KEIL MDK (Microcontroller Development Kit)

KEIL MDK는 이 코스에서 사용하는 또 다른 전문 개발 툴셋이다.

- IAR Embedded Workbench와 대조적으로, KEIL MDK는 점점 더 관대한 라이선스로 제공되어 왔고, **무료 KEIL MDK v6 Community Edition**도 포함한다.
- 코스는 **21강부터 KEIL MDK를 사용**했지만, **1~21강 전체에도 KEIL용 프로젝트 버전이 추가**됐다. 1~21강은 원래 IAR Embedded Workbench 또는 TI Code Composer Studio로 발표됐었다.

---

## 7. KEIL MDK 설치 절차

1. **KEIL Micro-Vision을 다운로드**한다. 다운로드 페이지에서 "Download KEIL MDK"를 클릭한다.
2. **ARM Developer 포털에 로그인**한다. 계정이 없으면 먼저 등록해야 한다. 로그인하면 최신 MDK 에디션을 다운로드할 수 있다.
3. MDK 설치는 간단하다. **MDK 툴셋과 "MDK Packs"의 기본 위치는 그대로 둬도 괜찮다.**
4. 설치 마지막 단계에서 KEIL **"Pack Installer"**가 실행되는데, 지금은 닫아도 된다. Pack의 용도는 KEIL uVision 프로젝트를 열어 보면 명확해진다.

### Device Family Pack — 프로젝트를 처음 열 때

KEIL 프로젝트를 처음 열면(예: 1강 프로젝트를 파일 탐색기에서 더블클릭) **"Device Family Pack이 없다"는 다이얼로그**가 뜬다.

이게 뜨는 이유: 그 프로젝트가 특정 디바이스(이 경우 **TM4C**)를 사용하는데, 그 디바이스에 대한 정보가 툴셋에 아직 없기 때문이다. **"Install"**을 클릭하면 Pack Installer가 해당 디바이스를 자동으로 다운로드·설치한다.

> Device Family Pack은 "이 칩이 어떤 칩인지"를 툴셋에 알려 주는 정보 묶음이다. 칩마다 메모리 맵·주변장치·레지스터가 다르므로, 프로젝트가 쓰는 칩에 맞는 Pack이 있어야 빌드·디버깅이 된다.

### 라이선스 설치

1. 메뉴에서 **File → License Management**를 선택한다.
2. 다이얼로그에서 **"Get License via Internet"**을 클릭한다.
3. arm-keil 웹사이트로 이동하면 긴 등록 폼을 채워야 한다.
4. 결국 이메일로 **MDK Community 라이선스**를 받는다.

## 8. Stellaris ICDI 디버거 문제 (TivaC + KEIL)

KEIL MDK로 TivaC LaunchPad를 쓸 때 마지막으로 해결해야 할 문제가 있다. TivaC의 디버거인 **Stellaris ICDI(In-Circuit Debug Interface)**에 관한 것이다.

증상 확인:

1. Project view에서 Debug 타겟 메뉴를 우클릭하고 **"Options for Target Debug"**를 선택한다.
2. **Debug 탭**을 클릭하고 드롭다운 목록을 펼친다.
3. 목록에 **Stellaris ICDI가 없다.** KEIL MDK가 기본적으로 더 이상 Stellaris ICDI를 지원하지 않기 때문이다.

해결:

1. 이 코스의 companion 웹페이지에서 **MDK extension**을 다운로드한다.
2. 받은 installer를 실행한다.
3. 이후 TivaC용 KEIL 프로젝트를 열면 Stellaris ICDI 디버거를 선택할 수 있다.

### 폴더 구조 (영상과 달라진 점)

프로젝트 구조는 영상에서 보이는 것과 **달라졌다**. 새 구조는 여러 임베디드 보드·툴셋을 수용하고 향후 확장성을 갖도록 **계층적으로** 정리됐다.

```
lesson-04/                ← 강의 번호 디렉터리 (예: 4강)
├── tm4c123/              ← 보드: TivaC (약칭 tm4c123)
│   ├── iar/              ← 툴셋: IAR
│   │   └── (프로젝트, 소스코드, 필요한 모든 코드)
│   └── keil/             ← 툴셋: KEIL
│       └── (프로젝트, 소스코드, 필요한 모든 코드)
└── stm32c031/            ← 보드: STM32 NUCLEO (약칭 stm32c031)
    ├── iar/
    └── keil/
```

규칙:

- 강의 디렉터리는 `lesson-04`처럼 강 번호로 명명된다.
- 그 안에 **보드 이름** 서브디렉터리: TivaC는 `tm4c123`, STM32 NUCLEO는 `stm32c031`.
- 그 다음 **툴셋 이름** 서브디렉터리: `iar`, `keil` 등.
- 최종 서브디렉터리 안에 해당 툴셋용 실제 프로젝트, 소스코드, 그리고 프로젝트가 필요로 하는 다른 모든 코드가 들어 있다. 이렇게 해서 프로젝트는 **self-contained하며 외부 의존성이 없다.**

> **예외**
> 시뮬레이터 프로젝트는 특수 케이스다. 물리 보드가 필요 없지만, 그래도 구체적인 타겟(보통 TivaC) 기준으로 준비되어 있다.

## 면접 답변 (30초 분량)

> `/easy-quiz` 실행 시 이 섹션이 정답 카드로 사용됩니다.

주제: **임베디드 개발 환경의 구성과 하드웨어 디버거의 역할**

- **한 줄 정의:** 임베디드 개발 환경은 임베디드 보드(하드웨어)와 개발 툴셋(소프트웨어)으로 구성되며, 그중 보드에 내장된 하드웨어 디버거가 학습의 핵심 도구다.
- **왜 필요:** 임베디드 개발은 PC 프로그램과 달리 코드가 별도의 MCU 위에서 돈다. 그 안에서 무슨 일이 일어나는지 보려면 CPU 내부를 들여다볼 수단이 필요하다.
- **동작:** TivaC LaunchPad나 STM32 NUCLEO 같은 보드는 하드웨어 디버거를 내장한다(TivaC는 Stellaris ICDI). 이 디버거가 single-step 실행과 CPU 내부 상태(레지스터·메모리) 검사를 가능하게 해 머신 레벨 동작을 직접 확인할 수 있다. 툴셋(IAR, KEIL MDK)은 컴파일과 디버깅을 담당하며, 프로젝트가 쓰는 칩에 맞는 Device Family Pack이 있어야 빌드된다.
- **비교:** PC용 개발이 OS와 표준 디버거에 의존하는 것과 달리, 임베디드 개발은 타겟 칩별로 보드·드라이버·툴셋·디바이스 Pack을 각각 맞춰야 한다. 그래서 ARM Cortex-M처럼 널리 쓰이는 단일 아키텍처 지식이 채용에서 큰 가치를 가진다.
- **30초 통합 답변:**
  > 임베디드 개발 환경은 임베디드 보드와 개발 툴셋 두 가지로 구성됩니다. PC 프로그램과 달리 코드가 별도의 MCU 위에서 돌기 때문에, 내부에서 무슨 일이 일어나는지 보려면 CPU 안을 들여다볼 수단이 필요합니다. 그래서 TivaC LaunchPad나 STM32 NUCLEO 같은 학습용 보드는 하드웨어 디버거를 내장하고 있고, 이게 single-step 실행과 레지스터·메모리 같은 CPU 내부 상태 검사를 가능하게 해서 머신 레벨 동작을 직접 확인할 수 있게 해 줍니다. 소프트웨어 쪽은 IAR나 KEIL MDK 같은 툴셋이 컴파일과 디버깅을 맡고, 프로젝트가 쓰는 칩에 맞는 Device Family Pack이 있어야 빌드가 됩니다. PC 개발이 OS와 표준 환경에 의존하는 것과 달리 임베디드는 타겟 칩마다 보드·드라이버·툴셋을 맞춰야 하므로, ARM Cortex-M처럼 널리 쓰이는 아키텍처 지식이 채용에서 특히 가치 있습니다.

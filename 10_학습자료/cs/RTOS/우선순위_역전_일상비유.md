## 등장인물 — 회사 사무실

회사에 직원 3명. **공용 회의실 1개**가 있고, 회의실 키는 1개뿐.

| 인물 | 직급 | 하는 일 |
|------|------|---------|
| **막내** | 사원 | 잡일 (예: 비품 정리) |
| **김대리** | 대리 | 보통 업무 (예: 보고서 작성) |
| **사장** | 사장 | 긴급 결재 (회의실에서만 가능) |

**규칙:**
1. 사장이 오면 무조건 사장 일이 먼저. 사원·대리 하던 일 멈추고 비켜야 함.
2. 대리가 오면 사원이 비켜야 함.
3. 회의실 쓰려면 키가 필요. 한 명만 들어감.

## 사고 진행 (우선순위 역전)

```
오전 9시  막내가 회의실 키 가져감 (비품 박스를 회의실에 잠깐 둠)
오전 9시 5분  사장 출근. 긴급 결재할 게 있어서 회의실 가려 함
              → 키 없음. 막내가 가지고 있음
              → "막내 비품 정리 빨리 끝내고 키 줘"
              → 사장은 자리에서 대기

오전 9시 10분  김대리 출근. 보고서 작성 시작
              → 막내가 비품 정리 중인 거 보고 "야 너 잠깐 비켜, 내 일이 더 급해"
              → 막내 일 멈춤. 김대리 자리에 앉아서 보고서 작성

오전 11시  김대리 보고서 한참 작성 중...
            ↓
            막내: 회의실 키 가진 채로 멈춰있음
            사장: 회의실 키 기다리며 대기 (★ 2시간째 ★)

오후 1시  김대리 보고서 끝남
오후 1시 5분  막내 다시 비품 정리 → 키 반납
오후 1시 10분  그제야 사장 회의실 사용
```

**문제:** 사장이 **2시간** 동안 대리 때문에 막힘. 위계가 거꾸로 뒤집힘 → **우선순위 역전**.

## 해결책 — 우선순위 상속

> 규칙 하나 추가: **"사장이 기다리는 키를 가진 사람은, 키 반납할 때까지 임시로 사장급 대우."**

같은 상황 다시:

```
오전 9시  막내가 회의실 키 가져감
오전 9시 5분  사장 출근, 키 기다림
            → 회사 규칙 발동
            → 막내, 임시로 "사장급"으로 승격됨
            → (한정: 키 반납할 때까지만)

오전 9시 10분  김대리 출근
              → 막내한테 "비켜" 하려는데
              → 막내가 지금 사장급
              → 김대리 못 밀어냄. 대기

오전 9시 20분  막내 빠르게 비품 정리 끝내고 키 반납
              → 막내 다시 원래 "사원"으로 복귀
오전 9시 21분  사장 즉시 회의실 사용
오전 9시 30분  사장 결재 끝남
              → 그 다음 김대리 보고서 작성 시작
```

**핵심:**
- 사장은 25분만 기다림 (2시간 → 25분)
- 김대리가 못 끼어들어서 막내가 빨리 끝낼 수 있었음
- 끝나면 막내는 원래 직급으로 돌아옴

## 컴퓨터 용어 대응표 (필요할 때만 봄)

| 일상 비유 | RTOS 용어 |
|-----------|-----------|
| 회사 직원 | 작업(task) |
| 직급 | 우선순위(priority) |
| 사장이 일을 시키면 직원이 멈춤 | 선점(preemption) |
| 회의실 키 | 뮤텍스(mutex) |
| 회의실 | 공유 자원 / 임계 구역 |
| "사장급으로 임시 승격" | 우선순위 상속(priority inheritance) |
| "직급 뒤집힘" | 우선순위 역전(priority inversion) |

---

## 한 줄 요약

> **사장이 기다리는 키 가진 막내를, 키 돌려줄 때까지 사장급으로 임시 대우 → 대리가 못 끼어들어서 막내가 빨리 끝냄 → 사장도 빨리 일함.**

## 실제 사고 예 (참고)

**1997년 화성 탐사선 패스파인더(Mars Pathfinder)**
- 우선순위 역전 발생 → 시스템 watchdog이 "뭔가 멈췄다"고 판단 → 재부팅 반복
- NASA가 우선순위 상속 기능을 원격으로 켜서 해결

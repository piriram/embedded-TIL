# `volatile` 오·남용 주의

> 출처: `붙여넣은 마크다운(1)(7).md`
> 최종 갱신: 확인 불가

---

## 30초 통합 답변

> 면접 직전 이것만 소리내어 읽는다. 입에 붙을 때까지.

`volatile` 오·남용 주의란 **`volatile`을 성능 향상 도구로 착각하거나 모든 변수에 붙이는 실수를 피해야 한다는 원칙**입니다. `volatile`은 주로 IO 레지스터, 인터럽트 공유 변수, busy-wait counter처럼 컴파일러 최적화가 실제 동작을 깨뜨릴 수 있는 경우에 정확성을 위해 사용합니다. 내부적으로는 해당 객체의 읽기·쓰기를 매번 실제 메모리 접근으로 남기도록 하므로, 컴파일러의 캐싱·제거·재사용 최적화를 제한합니다. 일반 변수에 불필요하게 붙이면 최적화 기회를 잃고 성능이 떨어질 수 있다는 점이 핵심입니다.

---

## 한 줄 정의

`volatile`은 **성능을 높이는 키워드가 아니라, 외부 변화 가능성이 있는 객체의 접근을 보존하기 위한 정확성 도구**이다.

핵심 특성은 **필요한 곳에만 제한적으로 써야 한다는 것**이다.

## 왜 필요한가

`volatile`은 컴파일러에게 다음과 같이 말하는 효과가 있다.

```text
이 객체는 네가 보기에는 그대로여도 외부에서 바뀔 수 있으니,
읽기·쓰기를 함부로 캐싱하거나 제거하지 말라.
```

이 지시는 IO 레지스터처럼 실제로 외부 변화가 있는 객체에는 필요하다.

하지만 일반 변수에 남발하면 컴파일러가 원래 할 수 있던 최적화를 못 한다.

예를 들어 일반 계산용 변수는 CPU 레지스터에 올려두고 빠르게 처리할 수 있다.

```c
int sum = 0;

for (int i = 0; i < 1000; ++i) {
    sum += i;
}
```

그런데 불필요하게 `volatile`을 붙이면 컴파일러는 매번 메모리 접근을 보존해야 하므로 최적화 여지가 줄어든다.

```c
volatile int sum = 0;

for (int i = 0; i < 1000; ++i) {
    sum += i;
}
```

이 경우 `volatile`은 정확성에 도움을 주지 않으면서 최적화만 방해할 수 있다.

## 동작 원리

일반 객체는 컴파일러가 다음과 같이 최적화할 수 있다.

- 값을 CPU 레지스터에 보관
- 중복된 메모리 읽기 제거
- 사용되지 않는 쓰기 제거
- 결과에 영향 없는 루프 제거
- 일부 접근 순서 재배치

반면 `volatile` 객체는 소스 코드에 적힌 접근이 관찰 가능한 동작으로 취급된다. 따라서 컴파일러는 해당 객체에 대한 읽기와 쓰기를 함부로 없애거나 재사용할 수 없다.

즉, `volatile`은 "더 빠르게 해달라"가 아니라 다음 의미다.

```text
이 접근은 외부 세계와 연결되어 있을 수 있으니 반드시 남겨라.
```

그래서 `volatile`은 보통 성능을 높이는 쪽이 아니라, 필요한 최적화를 일부 포기하고 정확성을 보장하는 쪽에 가깝다.

## 언제 쓰는가 / 언제 피하는가

- **쓰는 경우:** MMIO 레지스터, GPIO 입력/출력 레지스터, 하드웨어 상태 플래그, 인터럽트 핸들러가 변경하고 main loop가 읽는 단순 플래그, busy-wait delay loop의 counter, 컴파일러가 제거하면 안 되는 의도적 메모리 접근에 사용한다.

예:

```c
#define GPIO_PORTF_DATA_R  (*((volatile unsigned long *)0x400253FC))
```

```c
volatile unsigned int counter;

for (counter = 0; counter < 1000000; ++counter) {
}
```

- **피하는 경우:** 일반 계산용 지역 변수, 외부 요인으로 바뀌지 않는 데이터, 단순히 "최적화가 무서워서" 붙이는 경우, 성능을 높이기 위해 붙이는 경우, 멀티스레드 동기화를 `volatile`만으로 해결하려는 경우에는 피한다.

잘못된 예:

```c
volatile int a;
volatile int b;
volatile int result;

result = a + b;
```

외부 변화 가능성이나 하드웨어 접근 의미가 없다면, 이런 식의 `volatile` 남발은 컴파일러 최적화를 방해할 뿐이다.

## 대표 예시

### 적절한 사용: IO 레지스터

```c
#define GPIO_PORTF_DATA_R  (*((volatile unsigned long *)0x400253FC))

GPIO_PORTF_DATA_R = 0x02;
```

이 경우 쓰기 동작은 단순 변수 저장이 아니라 하드웨어 GPIO 출력에 영향을 주는 store다. 컴파일러가 제거하면 안 된다.

### 적절한 사용: delay loop counter

```c
volatile unsigned int counter;

for (counter = 0; counter < 1000000; ++counter) {
}
```

이 경우 루프의 계산 결과는 중요하지 않지만, 루프가 소비하는 시간이 목적이다. `volatile`이 없으면 최적화로 루프가 제거될 수 있다.

### 부적절한 사용: 일반 계산 변수

```c
volatile int x = 10;
volatile int y = 20;
volatile int z = x + y;
```

`x`, `y`, `z`가 외부 하드웨어나 인터럽트와 관련 없는 일반 계산 값이라면 `volatile`은 불필요하다. 이 경우 컴파일러가 레지스터를 활용하거나 중복 접근을 줄이는 최적화를 하기 어려워진다.

## 비교 / 대안

| 비교 대상 | 핵심 차이 |
|----------|-----------|
| `volatile` | 외부 변화 가능성이 있는 객체의 읽기·쓰기를 보존한다. 성능 도구가 아니라 정확성 도구다. |
| 일반 변수 | 컴파일러가 자유롭게 최적화할 수 있다. 외부 변화 가능성이 없다면 보통 이쪽이 맞다. |
| `const` | 값을 수정하지 않겠다는 의미다. 외부 변화 가능성을 알리는 기능이 아니다. |
| `atomic` | 멀티스레드에서 원자성과 메모리 순서를 다룬다. `volatile`과 목적이 다르다. |
| 하드웨어 timer | 정확한 시간 지연에는 busy-wait `volatile` loop보다 더 적합한 경우가 많다. |

## 꼬리질문 예상

- **Q:** `volatile`을 붙이면 코드가 빨라지나요?
  **A:** 아니다. 보통 반대다. `volatile`은 최적화를 제한하므로 성능이 떨어질 수 있다. 목적은 성능이 아니라 정확성이다.

- **Q:** 모든 변수에 `volatile`을 붙이면 안전한가요?
  **A:** 아니다. 불필요한 `volatile`은 최적화를 막고 코드 성능을 떨어뜨린다. 외부 변화 가능성이 있는 객체에만 써야 한다.

- **Q:** `volatile`을 안 쓰면 항상 버그인가요?
  **A:** 아니다. 일반 계산 변수에는 필요 없다. IO 레지스터, 인터럽트 공유 플래그, delay loop counter처럼 컴파일러 최적화가 실제 의미를 깨뜨릴 수 있는 경우에 필요하다.

- **Q:** `volatile`은 멀티스레드 동기화 도구인가요?
  **A:** 아니다. `volatile`은 원자성이나 thread-safety를 보장하지 않는다. 멀티스레드 동기화에는 atomic, mutex, memory barrier 같은 도구가 필요하다.

## 자주 하는 오해

- **오해:** `volatile`은 성능 최적화 키워드다.
  - **정확히는:** `volatile`은 컴파일러 최적화를 제한하는 정확성 도구다. 필요한 접근을 실제 메모리 접근으로 남기기 위해 사용한다.

- **오해:** `volatile`을 많이 붙일수록 안전하다.
  - **정확히는:** 필요 없는 곳에 붙이면 최적화 손실만 생긴다. 정확성에 필요한 객체에만 붙여야 한다.

- **오해:** `volatile`은 모든 최적화를 끈다.
  - **정확히는:** 주로 해당 volatile 객체의 읽기·쓰기에 대한 제거, 캐싱, 재사용 같은 최적화를 제한한다. 프로그램 전체 최적화를 끄는 것은 아니다.

- **오해:** `volatile`이면 동시성 문제가 해결된다.
  - **정확히는:** `volatile`은 접근 보존을 위한 키워드일 뿐, 원자성·락·메모리 순서를 보장하지 않는다.

## 자주 놓치는 정확 표현

| 모호한 말 | 정확한 용어 |
|----------|-------------|
| 성능을 위해 volatile을 붙인다 | 정확성을 위해 volatile 접근을 보존한다 |
| volatile은 최적화 옵션이다 | volatile은 타입 한정자이며 특정 접근 최적화를 제한한다 |
| volatile을 붙이면 안전하다 | 외부 변화 가능성이 있는 객체의 접근 누락을 막을 뿐이다 |
| 메모리에 강제로 저장한다 | volatile 객체의 읽기·쓰기를 실제 접근으로 유지한다 |
| 모든 변수에 붙이면 된다 | 필요한 객체에만 붙여야 하며 남발하면 최적화 손실이 생긴다 |

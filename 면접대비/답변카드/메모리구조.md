## 30초 통합 답변

> 면접 직전 이것만 소리내어 읽는다. 입에 붙을 때까지.

메모리는 1바이트 단위의 우편함이 줄지어 있는 구조고, 각 칸마다 고유한 주소가 있습니다. 프로그램이 프로세스로 실행되면 운영체제가 메모리를 네 영역으로 나눠 할당합니다. Code 영역에는 기계어 명령어가, Data 영역에는 전역 변수와 static 변수가, Heap에는 malloc으로 동적 할당한 메모리가, Stack에는 지역 변수와 함수 호출 프레임이 쌓입니다. 함수를 호출하면 각 함수는 Stack 안에서 서로 독립적인 프레임을 가집니다.

---

## 한 줄 정의

프로세스 메모리는 실행 중인 프로그램에 OS가 할당한 공간이다. Code·Data·Heap·Stack 네 영역으로 나뉜다.

## 왜 필요한가

용도가 다른 데이터를 분리해 관리하기 위해서다. 수명과 접근 방식이 다른 데이터(상수 코드, 전역값, 동적 메모리, 지역값)를 한 영역에 섞으면 관리와 보호가 불가능하다.

## 동작 원리

Stack은 함수 호출마다 프레임이 차곡차곡 쌓이고(LIFO), 함수가 끝나면 가장 최근 프레임부터 자동으로 사라진다. Heap은 malloc 시점에 할당되고 free 전까지 유지된다. Data는 프로그램 시작부터 종료까지 살아 있다.

## 비교 / 대안

- **Stack vs Heap:** Stack은 컴파일 시점에 크기가 정해지고 함수 종료 시 자동 해제, Heap은 실행 중 크기 결정·수동 해제(free).
- **Data vs Stack:** Data는 프로그램 수명 내내 유지, Stack 지역 변수는 함수 범위 내에서만 유효.

---

## 꼬리질문 예상

- **Q:** Heap은 언제 쓰나요?
  **A:** 실행 중에 크기가 정해질 때, 함수 종료 후에도 메모리를 유지해야 할 때, Stack에 올리기 큰 데이터, 연결 리스트·트리 같은 노드 자료구조.

- **Q:** Stack에 큰 배열을 잡으면 어떻게 되나요?
  **A:** Stack 공간을 초과하면 Stack Overflow가 발생한다. 큰 데이터는 Heap에 할당해야 한다.

- **Q:** static 변수는 어느 영역에 있나요?
  **A:** Data 영역. 함수 안에 있어도 Stack이 아니라 Data에 저장돼 프로그램 종료까지 유지된다.

## 자주 놓치는 정확 표현

| 모호한 말 | 정확한 용어 |
|----------|-----------|
| 변수가 저장되는 곳 | 지역 변수는 Stack, 전역/static은 Data |
| 메모리를 잡는다 | Heap에 동적 할당(malloc)한다 |
| 함수마다 따로 있는 공간 | 함수 호출 프레임(Function Frame) |

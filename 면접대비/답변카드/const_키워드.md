# `const` 키워드

> 출처: 자체 작성
> 최종 갱신: 2026-05-30

---

## 30초 통합 답변

> 면접 직전 이것만 소리내어 읽는다.

`const`는 **객체의 값을 그 식별자를 통해서는 수정할 수 없음을 컴파일러에 알리는 타입 한정자**입니다. 단순히 "변하지 않는 값"을 표현하는 것이 아니라, **그 이름으로의 쓰기 시도를 컴파일 단계에서 에러로 막아 의도를 코드에 박아두는 장치**입니다. 임베디드에서는 두 방향으로 쓰입니다. 첫째, 큰 룩업 테이블이나 폰트 데이터처럼 변경되지 않는 데이터를 `const`로 선언해 ROM/Flash에 배치하고 귀한 RAM을 절약합니다. 둘째, 함수 파라미터에 `const`를 붙여 "이 함수는 이 포인터로 가리키는 데이터를 안 건드린다"는 계약을 명시해 호출자가 안심하고 넘기게 합니다. 포인터와 결합할 때는 `*` 기준 왼쪽에 붙으면 가리키는 대상이 const, 오른쪽에 붙으면 포인터 자체가 const라는 규칙을 정확히 구분해야 합니다. `volatile`과는 직교적으로 같이 쓸 수 있어, 메모리 매핑된 읽기 전용 하드웨어 레지스터에는 `const volatile`을 함께 붙입니다.

## 한 줄 정의

`const`는 **해당 식별자를 통한 객체 수정 시도를 컴파일러가 거부하도록 만드는 타입 한정자**다.

핵심은 **"객체가 불변"이 아니라 "이 이름으로는 못 바꾼다"는 의미**다.

## 왜 필요한가

세 가지 목적이 분리되어 있다.

1. **읽기 전용 데이터 ROM 배치**: 폰트, 룩업 테이블, 상수 메시지처럼 런타임에 안 바뀌는 데이터를 `const`로 선언하면 보통 ROM/Flash 영역에 배치된다. 임베디드에서 RAM은 KB 단위로 빠듯하고 Flash는 상대적으로 넉넉하므로 이 차이는 크다.

2. **함수 계약 명시**: 포인터 파라미터에 `const`를 붙이면 "이 함수는 이 데이터를 수정하지 않는다"가 시그니처에 박힌다. 호출자가 자기 버퍼를 안심하고 넘길 수 있고, 함수 안에서 실수로 쓰려 하면 컴파일 에러로 잡힌다.

3. **의도 표시 + 컴파일러 최적화 여지**: 일반 변수에 `const`를 붙이면 컴파일러가 값이 안 바뀐다는 가정 아래 더 적극적으로 상수 전파, 폴딩을 할 수 있다.

## 포인터 + const 조합 — 가장 헷갈리는 부분

규칙: `*` 기준으로 어느 쪽에 `const`가 있느냐만 본다.

```c
const int *p;        // p가 가리키는 int가 const. p는 다른 데 가리킬 수 있음.
int const *p;        // 위와 동일 (const 위치는 타입 왼/오 어디든 같음)
int *const p;        // p 자체가 const. 가리키는 int는 수정 가능.
const int *const p;  // 둘 다 const.
```

읽는 법(right-to-left):
- `const int *p` → `p` is a pointer to (int that is const)
- `int *const p` → `p` is a const pointer to (int)
- `const int *const p` → `p` is a const pointer to (int that is const)

실제 사용:

```c
void uart_send(const uint8_t *buf, size_t len) {
    // buf로 가리키는 데이터는 수정 불가 (호출자 보호)
    // buf 자체는 함수 안에서 buf++ 가능
}

void timer_isr_register(void (*const cb)(void)) {
    // cb 포인터 자체를 함수 안에서 못 바꿈 (실수 방지)
}
```

## 동작 원리

- `const` 객체에 쓰기를 시도하면 **컴파일 에러**가 난다 (런타임 검사가 아니다).
- 하지만 `const`를 캐스팅으로 떼어내면 컴파일러는 막지 못하고, 런타임에 메모리 보호가 있는 영역(ROM)이면 하드웨어가 fault를 낸다. 그게 아니면 그냥 정의되지 않은 동작이다.
- 컴파일러는 `const` 변수의 값을 캐싱하거나 상수로 인라인할 수 있다(`volatile`이 없으면).

```c
const int x = 10;
int *p = (int *)&x;   // const를 캐스팅으로 제거 (위험)
*p = 20;              // 컴파일 통과. 런타임 동작은 정의되지 않음.
```

## 임베디드에서 자주 쓰는 패턴

### 1. 룩업 테이블 ROM 배치

```c
const uint16_t sin_table[256] = {
    0, 402, 804, 1206, /* ... */
};
```

이 256 × 2바이트 = 512바이트가 Flash에 박힌다. RAM 사용 0.

### 2. 읽기 전용 하드웨어 레지스터

```c
#define ADC_DR (*(const volatile uint32_t *)0x4001244C)
```

- `volatile`: 값이 외부에서 바뀐다 → 캐싱 금지
- `const`: 소프트웨어가 여기에 쓰면 안 된다 → 실수 방지

### 3. 함수 파라미터 계약

```c
void mpu6050_parse_accel(const uint8_t *raw, int16_t *out) {
    out[0] = (raw[0] << 8) | raw[1];
    // raw[0] = 0; ← 컴파일 에러
}
```

호출자는 자기 버퍼가 안 변할 거라 확신할 수 있다.

### 4. 매크로 대신 const

```c
#define BUFFER_SIZE 64        // 전처리기. 타입 정보 없음.
const size_t BUFFER_SIZE = 64; // 타입 안전. 디버거에서 보임.
```

단, 배열 크기로 쓰려면 C에서는 `#define`이나 `enum`을 써야 한다(C++와 다름).

## 비교 / 대안

| 비교 대상 | 핵심 차이 |
|----------|-----------|
| `#define` | 전처리기. 타입 검사 없음. 디버거에서 안 보임. |
| `enum` 상수 | 정수형으로 제한. 배열 크기로 사용 가능. |
| `static const` | 같은 모듈 안에서만 보이는 const. ROM 배치 + 가시성 제한. |
| `volatile` | 외부에서 값이 바뀜을 표시. const와 직교 — 같이 쓸 수 있다. |
| `final` (Java/C++) | C에는 없는 개념. 클래스/메서드 상속 차단. |

## 꼬리질문 예상

- **Q:** `const int *p`와 `int *const p`의 차이는?
  **A:** 전자는 가리키는 int가 const, 즉 `*p = x` 불가. 후자는 포인터 자체가 const, 즉 `p = &y` 불가.

- **Q:** `const` 변수를 캐스팅으로 수정하면 어떻게 되나요?
  **A:** 컴파일은 통과한다. 그러나 동작은 정의되지 않는다. ROM에 배치된 데이터면 하드웨어 fault, RAM에 있어도 표준상 미정의 동작이다.

- **Q:** 함수 파라미터에 `const`를 붙이는 이유는?
  **A:** 함수가 그 데이터를 수정하지 않음을 호출자에게 보장하고, 함수 내부 실수도 컴파일러가 잡게 한다.

- **Q:** `const volatile`은 언제 쓰나요?
  **A:** 소프트웨어는 못 쓰지만 하드웨어가 값을 바꾸는 읽기 전용 레지스터(상태 레지스터, ADC 데이터 레지스터 등)에 쓴다.

- **Q:** `const`는 메모리 절약 효과가 있나요?
  **A:** 그 자체가 메모리를 줄이지는 않는다. 그러나 컴파일러/링커가 const 데이터를 ROM에 배치하도록 결정해 RAM을 아낄 수 있다.

## 자주 하는 오해

- **오해:** `const`는 값이 절대 안 바뀐다는 뜻이다.
  - **정확히는:** 그 식별자로는 못 바꾼다는 뜻이다. 캐스팅이나 다른 포인터로는 바꿀 수 있다(미정의 동작이지만 컴파일은 통과).

- **오해:** `const`를 붙이면 자동으로 ROM에 들어간다.
  - **정확히는:** 컴파일러와 링커 스크립트의 결정이다. 보통은 그렇지만 보장된 동작이 아니다.

- **오해:** `const`는 성능 최적화 키워드다.
  - **정확히는:** 주 목적은 의도 표현과 실수 방지다. 최적화 여지는 부차적 효과.

- **오해:** `const int *p`는 `p`를 못 바꾼다는 뜻이다.
  - **정확히는:** `p`가 가리키는 데이터를 못 바꾼다는 뜻이다. `p` 자체는 다른 곳을 가리킬 수 있다.

# `unsigned int` vs `unsigned long`

> 출처: `붙여넣은 마크다운(1)(7).md`
> 최종 갱신: 확인 불가

---

## 30초 통합 답변

> 면접 직전 이것만 소리내어 읽는다. 입에 붙을 때까지.

`unsigned int`와 `unsigned long`은 **C의 부호 없는 정수 타입**입니다. 주로 레지스터 폭이나 정수 데이터 크기를 표현할 때 사용하며, 타입의 실제 크기는 C 표준이 고정하지 않고 구현과 플랫폼에 따라 달라집니다. 다만 강의에서 다룬 32비트 ARM 환경에서는 `int`와 `long`이 모두 32비트이므로 `unsigned int *`와 `volatile unsigned long *`는 레지스터 접근 폭 관점에서 실질적으로 같은 32비트 접근을 의미합니다. 실제로는 벤더 헤더 파일이 `volatile unsigned long *` 형태로 MMIO 레지스터 매크로를 정의하고, 직접 작성한 예제는 `unsigned int *`를 사용했다는 차이가 있습니다.

---

## 한 줄 정의

`unsigned int`와 `unsigned long`은 **부호 없는 정수 타입이며, 실제 비트 폭은 플랫폼 ABI에 의해 결정된다**.

핵심 특성은 **32비트 ARM 환경에서는 둘 다 32비트라서 MMIO 레지스터 접근 폭에서는 실질적으로 동등하다는 것**이다.

## 왜 필요한가

벤더 헤더 파일의 레지스터 매크로와 직접 작성한 매크로를 비교하면 타입 표기가 다르게 나온다.

```c
// 직접 작성
#define MY_REG   (*((unsigned int *)0x40025000))

// 벤더 헤더
#define HW_REG   (*((volatile unsigned long *)0x40025000))
```

처음 보면 `unsigned int`와 `unsigned long`이 서로 다른 크기라서 접근 방식도 다를 것처럼 보일 수 있다.

하지만 강의 노트의 대상 환경은 32비트 ARM 계열이다. 이 환경에서는 `int`와 `long`이 모두 32비트로 다뤄지므로, 레지스터 접근 폭 관점에서는 둘 다 32비트 정수 접근을 만든다.

따라서 이 비교에서 더 중요한 차이는 `unsigned int`냐 `unsigned long`이냐가 아니라, 벤더 헤더 쪽에 **`volatile`이 붙어 있다는 점**이다.

## 동작 원리

C에서 `unsigned int`와 `unsigned long`은 모두 부호 없는 정수 타입이다. 다만 C 표준은 이 타입들의 정확한 비트 수를 모든 플랫폼에서 하나로 고정하지 않는다.

강의 맥락의 32비트 ARM에서는 다음처럼 이해하면 된다.

| 타입 | 강의 대상 32비트 ARM에서의 크기 |
|------|-------------------------------:|
| `unsigned int` | 32비트 |
| `unsigned long` | 32비트 |

따라서 다음 두 포인터 타입은 모두 32비트 폭의 정수 객체를 가리키는 포인터로 쓰인다.

```c
unsigned int *
unsigned long *
```

MMIO 레지스터 주소가 32비트 레지스터를 가리키는 경우, 두 타입 모두 32비트 load/store 접근을 표현하는 데 사용될 수 있다.

단, 이 설명은 **강의에서 다루는 32비트 ARM 환경 기준**이다. 다른 ABI나 플랫폼에서는 `long`의 크기가 달라질 수 있으므로, 일반론으로 "항상 같다"고 말하면 안 된다.

## 언제 쓰는가 / 언제 피하는가

- **쓰는 경우:** 32비트 MCU 레지스터를 직접 접근할 때 다음과 같은 형태가 쓰일 수 있다.

```c
#define REG_A   (*((unsigned int *)0x40025000))
```

벤더 헤더에서는 다음처럼 정의될 수 있다.

```c
#define REG_B   (*((volatile unsigned long *)0x40025000))
```

이 강의의 핵심 비교에서는 두 타입 모두 32비트 접근이라는 점보다, `volatile` 포함 여부가 더 중요하다.

- **피하는 경우:** 플랫폼 독립적인 코드에서 `int`나 `long`의 크기를 암묵적으로 가정하면 안 된다.

예를 들어 다음처럼 "`long`은 항상 32비트"라고 가정하는 코드는 이식성이 낮다.

```c
unsigned long reg_value;  // 항상 32비트라고 단정하면 위험
```

정확한 폭이 중요하면 보통 고정 폭 정수 타입을 고려한다.

```c
#include <stdint.h>

uint32_t reg_value;
```

다만 실제 벤더 헤더는 해당 컴파일러와 MCU 환경에 맞게 타입을 정해 제공하므로, bare-metal 프로젝트에서는 벤더 헤더의 정의를 따르는 것이 일반적이다.

## 대표 예시

직접 작성한 레지스터 매크로:

```c
#define MY_REG   (*((unsigned int *)0x40025000))
```

벤더 제공 헤더의 레지스터 매크로 형태:

```c
#define HW_REG   (*((volatile unsigned long *)0x40025000))
```

비교 포인트:

```text
unsigned int   vs   unsigned long
```

강의 맥락의 결론:

```text
32비트 ARM에서는 둘 다 32비트 -> 레지스터 접근 폭 관점에서 실질적으로 동등
```

하지만 더 중요한 차이:

```text
volatile 없음   vs   volatile 있음
```

즉, 면접 답변에서는 다음처럼 말하는 것이 정확하다.

```text
이 강의의 32비트 ARM 환경에서는 unsigned int와 unsigned long이 모두 32비트라서
레지스터 접근 폭 측면에서는 실질적으로 동등합니다.
하지만 벤더 헤더의 핵심 차이는 unsigned long 자체보다 volatile이 붙어 있다는 점입니다.
```

## 비교 / 대안

| 비교 대상 | 핵심 차이 |
|----------|-----------|
| `unsigned int` | 부호 없는 정수 타입. 강의 대상 32비트 ARM에서는 32비트다. |
| `unsigned long` | 부호 없는 정수 타입. 강의 대상 32비트 ARM에서는 `unsigned int`와 마찬가지로 32비트다. |
| `uint32_t` | 정확히 32비트인 부호 없는 정수 타입을 의도할 때 더 명시적이다. |
| `volatile unsigned long` | 하드웨어 레지스터처럼 외부 변화 가능성이 있는 32비트 객체 접근을 보존하기 위해 사용된다. |

## 꼬리질문 예상

- **Q:** `unsigned int`와 `unsigned long`은 항상 같은 크기인가요?
  **A:** 아니다. C에서 정확한 크기는 플랫폼과 ABI에 따라 달라질 수 있다. 강의의 32비트 ARM 환경에서는 둘 다 32비트라서 실질적으로 동등하다는 의미다.

- **Q:** 벤더 헤더가 `unsigned long`을 쓴 이유가 성능 때문인가요?
  **A:** 이 강의 내용만으로 그 이유를 단정할 수는 없다. 강의에서 확인할 수 있는 핵심은 32비트 ARM에서는 `unsigned int`와 `unsigned long`이 모두 32비트이며, 더 중요한 차이는 `volatile`이 붙어 있다는 점이다.

- **Q:** MMIO 레지스터 매크로에서 더 중요한 것은 타입 크기인가요, `volatile`인가요?
  **A:** 둘 다 중요하지만, 이 비교에서는 `unsigned int`와 `unsigned long`이 모두 32비트이므로 타입 크기 차이는 실질적으로 작다. 핵심 차이는 `volatile`이 있어 실제 메모리 접근을 보존한다는 점이다.

- **Q:** 이식성을 높이려면 무엇을 쓰는 게 좋나요?
  **A:** 정확한 비트 폭이 중요한 일반 코드라면 `uint32_t`처럼 고정 폭 정수 타입이 더 명확하다. 다만 MCU 레지스터 접근에서는 벤더 헤더가 제공하는 타입 정의를 따르는 것이 보통이다.

## 자주 하는 오해

- **오해:** `unsigned long`은 항상 `unsigned int`보다 크다.
  - **정확히는:** 항상 그렇지 않다. 강의의 32비트 ARM 환경에서는 둘 다 32비트다.

- **오해:** 직접 작성 매크로와 벤더 매크로의 가장 중요한 차이는 `int`와 `long`이다.
  - **정확히는:** 강의 맥락에서는 둘 다 32비트이므로 실질적으로 동등하다. 더 중요한 차이는 벤더 헤더 매크로에 `volatile`이 붙어 있다는 점이다.

- **오해:** C 타입 이름만 보면 항상 비트 수를 알 수 있다.
  - **정확히는:** `int`, `long`의 정확한 크기는 구현과 ABI에 따라 달라진다. 정확한 크기가 필요하면 `stdint.h`의 고정 폭 타입을 확인해야 한다.

## 자주 놓치는 정확 표현

| 모호한 말 | 정확한 용어 |
|----------|-------------|
| `int`랑 `long`은 같다 | 이 32비트 ARM 환경에서는 둘 다 32비트다 |
| `long`이 더 크다 | 플랫폼에 따라 다르며, 여기서는 32비트로 실질 동등하다 |
| 타입 차이는 의미 없다 | 이 환경의 레지스터 접근 폭에서는 실질 차이가 작다 |
| 벤더 헤더는 `long`이라 다르다 | 핵심 차이는 `volatile unsigned long`처럼 `volatile`이 포함된 점이다 |
| 항상 32비트다 | 강의 대상 32비트 ARM 기준으로 32비트다 |

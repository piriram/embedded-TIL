# C Preprocessor / `#define` 매크로

> 출처: `붙여넣은 마크다운(1)(7).md`
> 최종 갱신: 확인 불가

---

## 30초 통합 답변

> 면접 직전 이것만 소리내어 읽는다. 입에 붙을 때까지.

`#define` 매크로는 **컴파일 전에 C Preprocessor가 수행하는 단순 텍스트 치환 규칙**입니다. 주로 하드코딩된 숫자 주소나 반복되는 코드 조각에 의미 있는 이름을 붙이기 위해 사용하며, 내부적으로는 컴파일러가 보기 전에 매크로 이름을 치환 텍스트로 바꾸는 방식으로 동작합니다. 일반 C 변수나 함수와 비교하면, 매크로는 타입 검사나 문법 검사 대상이 아니라는 점이 가장 중요합니다. 실제로는 MCU 레지스터 주소처럼 `0x400FE608` 같은 cryptic한 값을 `RCGCGPIO` 같은 의미 있는 이름으로 바꿀 때 특히 중요합니다.

---

## 한 줄 정의

`#define` 매크로는 **컴파일 이전에 특정 이름을 지정된 텍스트 조각으로 치환하는 전처리기 기능**이다.

핵심 특성은 **컴파일러가 매크로 이름 자체를 보지 못한다는 것**이다.

## 왜 필요한가

하드웨어 레지스터 주소나 반복되는 코드 조각을 그대로 쓰면 코드가 읽기 어렵고 실수하기 쉽다.

예를 들어 다음처럼 주소를 직접 쓰면 의미를 바로 알기 어렵다.

```c
(*((unsigned int *)0x400FE608)) = 0x20;
```

매크로를 쓰면 같은 코드를 의미 있는 이름으로 표현할 수 있다.

```c
#define RCGCGPIO   (*((unsigned int *)0x400FE608))

RCGCGPIO = 0x20;
```

이렇게 하면 `0x400FE608`이라는 숫자가 아니라, **GPIO clock control register에 접근한다**는 의도가 드러난다.

## 동작 원리

C Preprocessor는 컴파일러가 실제 C 코드를 해석하기 전에 먼저 실행된다.

`#define RCGCGPIO (*((unsigned int *)0x400FE608))`가 있으면, 전처리기는 이후 코드에 등장하는 `RCGCGPIO`를 그대로 `(*((unsigned int *)0x400FE608))`로 바꾼다. 그 뒤 컴파일러는 이미 치환된 코드만 보기 때문에 `RCGCGPIO`라는 매크로 이름은 알 수 없다.

중요한 점은 매크로가 **완성된 C 문법 요소일 필요가 없다는 것**이다. 매크로는 변수, 함수, 표현식처럼 문법적으로 독립된 단위가 아니어도 된다. 치환된 결과가 최종적으로 C 문법에 맞으면 컴파일된다.

예:

```c
#define REG_ADDR  ((unsigned int *)0x400FE608)

*REG_ADDR = 0x20;
```

전처리 후에는 다음처럼 된다.

```c
*((unsigned int *)0x400FE608) = 0x20;
```

`REG_ADDR` 자체는 완성된 대입문도 아니고 변수 선언도 아니지만, 치환된 결과가 문법적으로 맞기 때문에 통과한다.

## 언제 쓰는가 / 언제 피하는가

- **쓰는 경우:** 하드웨어 레지스터 주소, 상수값, 비트 마스크, 반복되는 짧은 코드 조각에 이름을 붙일 때 사용한다.
- **피하는 경우:** 타입 검사, 스코프, 디버깅 정보가 중요한 일반 로직에서는 가능하면 `const`, `enum`, `inline function`을 우선 고려한다. 매크로는 단순 텍스트 치환이라 타입 안전성이 낮고, 괄호를 빼면 예상과 다른 의미로 해석될 수 있다.

## 대표 예시

MCU의 GPIO 레지스터 접근 예시:

```c
#define GPIOF_BASE       0x40025000
#define GPIO_PORTF_DIR   (*((unsigned int *)(GPIOF_BASE + 0x400)))
#define GPIO_PORTF_DEN   (*((unsigned int *)(GPIOF_BASE + 0x51C)))
#define GPIO_PORTF_DATA  (*((unsigned int *)(GPIOF_BASE + 0x3FC)))
```

사용 코드:

```c
GPIO_PORTF_DIR  = 0x0E;
GPIO_PORTF_DEN  = 0x0E;
GPIO_PORTF_DATA = 0x02;
```

전처리 후 컴파일러가 보는 코드는 개념적으로 다음과 같다.

```c
(*((unsigned int *)(0x40025000 + 0x400))) = 0x0E;
(*((unsigned int *)(0x40025000 + 0x51C))) = 0x0E;
(*((unsigned int *)(0x40025000 + 0x3FC))) = 0x02;
```

여기서 `GPIO_PORTF_DATA` 같은 이름은 컴파일러 단계에서는 이미 사라진다.

## 비교 / 대안

| 비교 대상 | 핵심 차이 |
|----------|-----------|
| `const` 변수 | `const`는 C 언어의 변수 또는 객체이므로 타입과 스코프가 있다. `#define`은 컴파일 전 텍스트 치환이라 타입이 없다. |
| `enum` | 정수 상수에 이름을 붙일 때는 `enum`이 타입 검사와 디버깅 측면에서 더 안전할 수 있다. |
| `inline function` | 함수처럼 인자를 처리해야 하면 매크로보다 `inline function`이 타입 안전하다. |
| 일반 변수 | 일반 변수는 메모리 객체지만, 매크로는 메모리를 차지하지 않고 사용 위치에서 텍스트로 치환된다. |

## 꼬리질문 예상

- **Q:** 컴파일러는 매크로 이름을 알고 있나요?
  **A:** 아니다. 매크로 이름은 전처리 단계에서 치환되므로, 컴파일러는 치환된 결과만 본다.

- **Q:** 매크로는 반드시 완성된 C 표현식이어야 하나요?
  **A:** 아니다. 매크로 자체는 코드 조각이어도 된다. 중요한 것은 치환된 최종 결과가 C 문법에 맞는지다.

- **Q:** 정의만 하고 사용하지 않은 매크로도 컴파일에 영향을 주나요?
  **A:** 일반적으로 영향을 주지 않는다. 실제 사용된 매크로만 코드 안에서 치환된다.

- **Q:** 왜 매크로 정의에 괄호를 많이 쓰나요?
  **A:** 매크로는 어떤 문맥에 삽입될지 모르기 때문에, 연산자 우선순위나 결합 방식 때문에 의미가 바뀌는 것을 막기 위해 괄호로 감싼다.

## 자주 하는 오해

- **오해:** `#define` 매크로는 C 변수나 함수처럼 컴파일러가 이해하는 언어 요소다.
  - **정확히는:** 매크로는 컴파일러가 보기 전에 전처리기가 수행하는 텍스트 치환 규칙이다. 컴파일러는 매크로 이름이 아니라 치환된 C 코드만 본다.

- **오해:** 매크로는 항상 완성된 문장이나 표현식이어야 한다.
  - **정확히는:** 매크로 자체는 부분적인 코드 조각이어도 된다. 다만 치환이 끝난 최종 코드가 C 문법에 맞아야 한다.

- **오해:** 매크로를 쓰면 런타임에 치환 작업이 발생한다.
  - **정확히는:** 치환은 컴파일 전에 끝난다. 런타임에는 매크로라는 개념이 존재하지 않는다.
